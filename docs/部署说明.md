# Stargazer 部署说明

覆盖三种形态：开发环境（源码运行）、打包安装（单机 EXE）、本机升级。
密钥与私有路径只走本地文件，见文末"隐私与密钥清单"。

## 一、环境要求

- Windows 10/11 x64。
- Python 3.10+（开发/构建用；运行打包 EXE 不需要 Python）。
- 通达信本地日线数据（vipdoc 目录，作为行情基座）。
- 推荐运行目录独立（程序在其下创建 `data/` 等运行数据）。

## 二、首次部署（打包 EXE）

1. 将发布产物 `Stargazer.exe` 放入目标目录（例如 `stargazer_desktop\dist\`）。
2. 同目录放置配置文件 `config.yaml`（**不要**用仓库里的 example 直接顶替现有文件）：
   复制 `config.example.yaml` 为 `config.yaml` 后按本机填写：
   - `push.provider`：`dingtalk` / `serverchan` / `pushplus` 之一；
     - 钉钉：`dingtalk_webhook`（群机器人地址）+ `dingtalk_secret`（加签，SEC 开头）；
     - Server酱：`serverchan_sendkey`；PushPlus：`pushplus_token`；
   - 可选：`kimi.api_key`（助手模型）、`tavily.api_key`（资讯）。
3. 通达信路径（三选一，推荐前两种）：
   - 环境变量 `STARGAZER_TDX_ROOT` 指向 vipdoc 目录；或
   - 在 `data/tdx_root.txt` 写入 vipdoc 完整路径（该文件已 gitignore）；
   - 不设置时使用通用占位 `D:/tdx/vipdoc`。
4. 双击启动。首次启动会做基础自检并打开桌面窗口；右下角可核对构建号。
5. 首次使用：打开「交易计划」→ 盘后选股 → 展开草案 → 确认；配置好推送后点一次测试推送。

## 三、源码开发与构建

```bash
# 前端（React UI）
cd ui_next/frontend && npm install && npm run build   # 产物在 ui_next/artifacts/r<轮次>/，复制到 stargazer_desktop/web/

# 后端回归（示例，按目录内测试约定）
python _dev_venv/Scripts/python.exe stargazer_desktop/test_daily_tarot_v1.py

# 发布指纹清单（改动受绑定源码后必须走"指纹三锁"）
# 1. 先核对旧清单与源码零失配；2. 修改源码并切换 8 处运行时引用到新版本号；3. 运行 release_audit_v1 下的发布脚本生成后继清单（旧清单保留不覆盖）

# 打包（不覆盖正在运行的程序）
cd stargazer_desktop && build_windows.bat   # 输出 dist_candidate/Stargazer.exe 并自动做包校验
```

## 四、升级（换新版 EXE）

1. 关闭程序（含托盘）。
2. 备份现有 `dist\Stargazer.exe` 到安全位置。
3. 用候选 EXE 覆盖 `dist\Stargazer.exe`。
4. **不要动**这些运行数据（升级保留）：
   `config.yaml`、`data/`（计划、持仓、成交、观察名单、公告库、强势池、推送账本）、
   `data/local_records/`（正式计划权威存储）、`data/isolated/`（全球行情快照）。
5. 启动后核对右下角构建号与发布清单一致；异常时用备份回滚。

## 五、目录与数据说明（运行期生成，不入库）

| 路径 | 内容 |
|---|---|
| `config.yaml` | 本机配置（含推送密钥，gitignore） |
| `data/trade_plan.json` 等 | 计划/持仓/观察/成交等业务数据 |
| `data/local_records/` | 正式交易计划权威持久记录 |
| `data/pentacles_demo/` | 选股快照、助手计划、分析状态 |
| `data/postclose_risk/` | 强势池（pools/prep_jobs/maps/minutes）、触价与回执 |
| `data/isolated/` | 全球行情快照、隔离证据 |
| `data/tdx_root.txt` | 本机通达信路径覆盖（gitignore） |
| `PENTACLES_LEARNING.md` | 复盘学习记录 |

## 六、隐私与密钥清单（部署核对用）

- 永不入库：`config.yaml`、各 `tokens.yaml`、`.secrets/`、`data/` 全部、`dist/` 全部、模型权重、构建产物。
- 仓库只含占位模板：`*example.yaml`。部署时复制为本机文件再填真实值。
- 若发现仓库中出现任何真实 token/个人路径，立即撤销该密钥并联系维护者清理历史。

## 七、常见部署问题

| 现象 | 处理 |
|---|---|
| 启动后页面是旧版 | 完全退出后重启；服务端已对静态资源返回 no-store，一般重启即可 |
| 日线缺失（等待日线） | 先更新通达信本地日线到所需日期，再点"更新板块强势池"或等自动准备 |
| 推送"未配置" | 检查 config.yaml 的 provider 与对应密钥字段是否齐全；钉钉还需 secret |
| 单实例冲突 | 程序有单实例锁；先退出旧实例再启动 |
| 测试推送无反应 | 密钥错误/群机器人被禁言/网络不通，页面会显示服务端返回的真实原因 |
