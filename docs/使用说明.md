# Stargazer 使用说明（最新 UI）

本说明对应新 React UI（右下角页脚可见"构建 vNNN · 哈希"版本号）。
程序**不自动下单**：所有买卖都由你完成并在页面登记；程序只做观察、证据与提醒。

## 一、每日流程（推荐）

1. **开盘前**：保持程序运行。工作日 09:00 会收到"今日塔罗"推送。
2. **盘中**：程序按已确认计划自动监控（触价提醒、三选二组合、大盘闸门、板块扫描），推送走你配置的通道（钉钉/Server酱/PushPlus）。
3. **收盘后**：
   1. 打开「交易计划」页，点 **盘后选股**（按钮变"正在分析…"，约 10 分钟本地计算，完成显示数据日/观察日）；
   2. 待确认草案出现（默认折叠），点 **展开** 逐股核对；
   3. 需要改时：直接编辑字段，点 **保存修改（生成新版本草案）**；不要的点 **拒绝草案**（不影响现行计划）；
   4. 确认后进入监控。

## 二、各页面

### 总览
计划、持仓、观察名单、Corvus 重要信息、待处理事项一页速览。刷新按钮带"刷新中…/刷新完成 时间"反馈。

### 交易计划（核心）
- **三个按钮**：刷新（只读重取）｜盘后选股（显式本地分析）｜按最新证据重新分析（与助手讨论，可能调用 DeepSeek，会明确提示）。
- **待确认草案**：默认折叠；可编辑后另存新版本草案；拒绝走独立拒绝语义，不取消现行计划。
- **当前生效计划**：每只股票的来源、关注区、入场规则说明（如"三选二：位置到达必要，修复/动能/超卖任意两项成立"）、有效期、放弃条件。过期计划如实显示，不冒充有效。
- **监控板块强势股**（与正式选股分开）：
  - 逐板块显示：身份/成员来源日期/成员数/准备状态/合格数；
  - 状态分五类：就绪（筛选完成 N 只）/ 准备中 / 失败（含原因）/ 等待日线 / 历史结果（过期标注）；
  - **点击板块名展开**真实股票：代码、名称、黄金观察区（仅观察数据，不自动加入个股计划）；
  - **更新板块强势池**：显式补准备；准备中自动轮询（有界，完成自动显示；长期未变显示"自动刷新已暂停"可手动重新查询）；
  - 历史成员会注明快照日期（如 2026-10-17），当日抓取成分单独标注。

### Stargazer 助手
对话为主。可自然语言下达："把光伏概念板块加入监控板块""把 XX 的关注区改为 a-b""帮我看 300652"。
仅改板块不会触发重新选股；混合修改（板块+个股）走完整校验。复盘页可一键"去助手复盘"并自动带入上下文。

### 复盘
选择日期与对象（持仓复盘/计划复盘/实际成交）→ 生成/核对 → 去助手交流补充 → 回本页**保存复盘**（幂等，刷新与重启后可读）。统计字段中文标注，区分实际成交与假设回放。

### 持仓
登记买入/卖出（**登记真实成交，不是券商下单**）。数量、加权成本、可卖（T+1）、盈亏自动按登记成交计算；同一请求重复提交不会重复登记；未登记成交时如实显示"未登记"。关联 Corvus 公告在持仓行显示（未导入则如实标注）。

### 观察名单
手工观察股票的新增/修改/删除，重启保留。手工观察与正式计划关联清晰。

### Corvus 信息
- **近期重要公告**：按披露时间真实筛选（近 30 天）；更早的入"历史公告"、日期未匹配的入"日期不可得公告"折叠区（不删除数据）。
- 主卡片：一句话概括、事实摘要（真实正文摘录，标注"摘录："）、可能影响（涉及标的+成立条件，不承诺涨跌）、披露时间、来源、原文链接（无则如实标注）。技术字段（D2/L0/证据坐标/SHA/版本）全部折叠在"展开证据"里。
- **全球市场**：美股指数、COMEX 金银、WTI/布伦特、日经 225、欧洲斯托克 50、中美 10Y 国债。启动时后台自动补采；也可点 **更新全球行情**。缺失/过期/样本均带状态标签，不拼造。

## 三、常见状态含义

| 显示 | 含义 |
|---|---|
| 身份已确认 / 成分待准备 / 监控已启用 | 板块三阶段状态：保存名称 ≠ 监控生效 |
| 就绪（筛选完成，0只） | 计算正常完成，只是没有合格股票，不是失败 |
| 等待日线 | 本地通达信日线未更新到所需日期，更新后自动继续 |
| 准备失败（含原因） | 失败原因直接可见；可重试的会标注 |
| 历史结果（过期） | 观察日已过，仅历史参考，不作当前就绪 |
| STALE（全球市场） | 报价时间超过有效窗口的旧数据 |
| 未知 / 未提供 | 后端确实没有该数据，不猜不补 |

## 四、提醒与推送

- 推送通道在配置中选择（钉钉需 webhook + 加签 secret）。
- 测试推送按钮会真实发一条到你的群。
- 关闭推送时只停外发，窗口内仍可见，**不消耗去重资格**；重开后同内容仍可发出。
- 已发送或送达未知的提醒不会盲目重发。

## 五、排障入口

- 页脚"构建 vNNN · 哈希"：核对正在运行的构建版本。
- 强势池任务文件、池文件与回执在程序数据目录的 `postclose_risk/strong_sector/`（只读查看，勿手工改）。
- 技术诊断在后台日志；页面操作失败会在对应位置简短提示，不静默成功。

## 六、配置参考

所有配置都在程序目录的 `config.yaml`（复制 `config.example.yaml` 后按本机填写）。
也可在程序的设置页直接修改（页面按钮会写回该文件）。

### 1. AI 模型（目前只支持 DeepSeek）

- **目前唯一接线的 LLM 提供商是 DeepSeek**（`stargazer_desktop/deepseek_api.py`，接口为 OpenAI 兼容调用）。
- **API Key 填在哪**：程序内打开「设置」页，找到 DeepSeek 密钥输入框填写。密钥经 Windows DPAPI
  加密后保存在本机用户目录（不随程序复制生效，换机需重填）。也可以用环境变量 `DEEPSEEK_API_KEY` 提供。
- **模型与参数**（`config.yaml`）：
  ```yaml
  deepseek:
    model: deepseek-flash   # 模型名
    max_tokens: 2000        # 单次输出上限（程序强制封顶 4000）
  ```
  每次调用都会记账（本地 sqlite，含失败调用），无静默重试；余额不足/超时/限流等错误在页面上按真实分类提示。
- **调用的地方**：盘后选股解释、计划讨论、复盘判读、每日塔罗润色。都属显式操作，不自动发请求。
- **想换成别的提供商**：目前没有切换开关，需要改代码，位置集中在
  `stargazer_desktop/deepseek_api.py` 的 `complete()` 函数：
  1. `base_url='https://api.deepseek.com'` 改为目标提供商的兼容接口地址；
  2. `extra_body={'thinking': {'type': 'disabled'}}` 是 DeepSeek 专属参数，其他提供商需删改；
  3. `MODEL` 默认值与 `status()` 里的 provider 文案；
  4. 密钥存储（DPAPI）通用，无需改动；改完走正常回归与指纹清单发布流程。

### 2. 行情数据源（本地通达信）

- **默认数据源是本机通达信 vipdoc 目录**（日线/5 分钟线，全部为本地文件读取，不上传行情）。
- **指向自己的通达信**（三选一）：
  1. 环境变量 `STARGAZER_TDX_ROOT` = 通达信 `vipdoc` 完整路径；
  2. 在程序目录新建 `data/tdx_root.txt`，写入完整路径（该文件已被 gitignore）；
  3. 都不设置时默认 `D:/tdx/vipdoc`（占位，需按实际改）。
- **要换成别的数据源**（例如直接读 parquet/数据库），目前没有切换开关，需改代码，涉及三处：
  1. `stargazer_desktop/tdx_daily_source_v2.py` 的 `daily_directory()`（日线分区位置）；
  2. `stargazer_desktop/sector_rule_scan.py` 的 `source_context()`（选股上下文：日历/日线分区/板块目录）；
  3. `stargazer_desktop/pentacles_demo.py` 的 `_default_daily()`（盘后选股默认日线目录）。
  注意：选股上下文会生成计算身份（source_key），改动会影响强势池复用关系。

### 3. 推送配置

`config.yaml` 的 `push:` 段（设置页也可改，字段一致）：

```yaml
push:
  enabled: true            # 总开关；关闭时只在窗口展示，不消耗外部去重资格
  provider: dingtalk       # serverchan | pushplus | dingtalk（三选一）
  serverchan_sendkey: ''   # Server酱 sendkey
  pushplus_token: ''       # PushPlus token
  dingtalk_webhook: ''     # 钉钉群机器人 webhook 地址（安全设置选"加签"）
  dingtalk_secret: ''      # 加签 secret（SEC 开头）；留空则不加签
  interval_minutes: 30     # 定时巡检间隔
  close_time: '15:05'      # 收盘巡检时间
  dedup_hours: 4           # 同内容去重窗口（小时）
  in_app_notify: true      # 窗口内同时展示
  morning_report: true     # 晨报（morning_time 触发）
  morning_time: 09:05
  stop_watch: true         # 持仓/观察盘中异常提醒
  auction_check: true      # 竞价检查（auction_time 触发）
  auction_time: 09:26
  daily_tarot:             # 每日塔罗（工作日 time 推送一次）
    enabled: true
    time: '09:00'
    use_llm: true          # false 用本地事实核，不调用付费模型
    persona: klein
```

- 每个通道只填对应字段即可，其余留空；测试推送按钮会真实发送一条验证。
- 推送回执与失败逐条记账，历史可查询；已发送/送达未知的内容不会盲目重发。
