# Stargazer 1.0 双供应商前瞻影子观察协议 V1（2026-10-20 冻结，待用户签数）

> 定位：**只记录、不影响**。影子建议并列展示；原候选、到价提醒、持仓风控照常；
> 买卖仍由用户决定。DeepSeek=默认展示，Kimi=对照；**不自动故障切换**。
> 旧 Run3 不改分；V1.4 口径重评已单独登记（18.36c）。"均可接受"≠两家能力相当。

## 1. 观察窗口（冻结）

- **窗口**：2026-10-21 ~ 2026-11-17（20 个交易日）。窗口外记录不入评价。
- 证据版本：窗口内全程 Pyxis 版本冻结（232主版 e589ea52… / 266对照 45672661…，
  哈希常量 oracles_v1.PYXIS_FROZEN）；**观察期内不换模型版本**。

## 2. 事件与调用额度（冻结）

| 触发类型 | 定义 | 日限额 |
|---|---|---|
| 首次触发 | 某候选当日首次 trigger 成立 | 每家 ≤5 次/日 |
| 重要风险变化 | amp_232 变动>50% 或 weakening 标记翻转（对同一候选） | 每家 ≤3 次/日 |
| 人工请求 | 用户在脚本/界面主动发起 | 记录但不限次 |

- **每家每日硬顶 8 次**；窗口总顶 160 次/家。单次超时 30s。
- **快照复用**：同一 pack_hash 且未过期 → 复用结果，不重复调用。
- 四家事件共用同一证据包构建脚本；两家读**同一时刻、同一版本**证据。
- 硬门短路=本地拦截，**不消耗额度、不记为供应商调用**。

## 3. 记录字段（评价表结构）

每条事件一行（shadow_journal.jsonl）：
`event_id / 时刻(query_ts) / 候选 / 触发类型 / pack_hash / 硬门结果(拦截原因或null) /
供应商 / 建议选项 / render展示(标题+下一步) / 反证识别(0/1) / 重评条件(0/1) /
延迟s / tokens / 费用 / 超时·过期标记 / 人工最终决定 / 7日后续结果(窗口后补)`

## 4. 评价表（冻结，分项报告不混算）

| 维度 | 口径 |
|---|---|
| 拦截 | 硬门拦截率（本地，分原因）——单独报告 |
| 可用 | 供应商建议可用率 = 通过门禁的建议数/实际调用数 |
| 失败 | 超时率、返回后过期率——单独列，不入可用率分母混淆 |
| 质量（仅对有建议的事件） | 反证识别率、重评条件给出率、行动一致性（与人工决定比）、选项稳定性（同事件重复运行） |
| 工程 | 延迟分布（中位/p90）、实际费用合计 |
| 后续（窗口满后） | 风险识别/误警/错失机会对照；**历史窗口表现不直接证明未来** |

## 5. 证据来源（如实登记）

- 星币候选字段：盘后从既有入口导出（v0 手工导出 + 构建脚本组装）。
- **Pyxis 活体逐日推理管线未建立**：风险证据不可用时硬门将如实记录
  EVIDENCE_INSUFFICIENT——这本身是影子数据（分母单列，不与"有建议"混算）。
- 每条记录留痕证据来源与构建时间；不使用未经登记的证据版本。

## 6. 退出与中止

- 任一家额度耗尽 → 该家停止记录（另一家继续）；两家均尽 → 窗口提前结束。
- 观察期**不换提示、不换模型、不据已见结果调阈值**；发现漏洞按修复流程走
  （登记→修→新案例验证），不回溯改分。
