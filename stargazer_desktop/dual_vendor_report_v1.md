# Stargazer 1.0 决策层双供应商对照报告（修订版 V1.1；2026-10-20）

## 方法（用户冻结口径）

同一证据包/同一供应商中性提示/同一输出结构（legal_refs 完全指定）；先过正确性门
（硬违规一票否决）；4 固定案例 ×3 重复隐藏标签盲评；费用延迟同录；差异不明确
不强行选胜者。

## 修订记录（对照初版）

1. **真实联调入口时间门漏洞已修**：初版 `run_case()` 直接调 `_validate_response()`
   绕过 `judge()` 的三时刻校验（用户实测：查询11:12/触发15:00 仍 PASS+买入确认）。
   已改为**统一走 `judge()`**：请求前校验（硬门+三时刻）与返回后校验同一条路径，
   mock 回归验证（`test_time_gate_active_in_real_entry`），**未重新付费跑旧案例**。
   据此，初版"零未来数据违规"**收窄为：这些固定输入上未发现违规；时间防线在
   初版真实入口未生效，现已生效**。
2. **风险缺失 3/3 归因更正**：来自**本地硬门短路，未发送供应商请求**——证明
   系统拦截正确，**不归为两家模型判断正确**。
3. **"稳定性"措辞更正**：仅 4 案例 ×3 重复；DeepSeek 在实际发送请求的 3 个
   场景选项一致，**不足以说明普遍更稳定；"一致"不等于"正确"**。
4. **费用口径更正**：只记录了 token 未记录计价金额，**费用结论撤回待核算**；
   DeepSeek 每次 token 反而更多；可保留"**本批成功响应平均延迟更短**
   （DeepSeek 11.8s vs Kimi 成功调用均值 17.2s）"；Kimi 1 次 30s 超时另列，
   不计入均值。

## 追加订正（2026-10-20，用户复核后）

- **调用分列**：JEV 轮（jev_run2）= **9 次真实供应商调用 + 3 次本地硬门拦截**（缺失案例，未消耗调用）——分列，不混算。
- **速度口径**：统一中位数对中位数——JEV 中位 **0.497s**；DeepSeek 11.8s 与 Kimi 17.2s 为**成功调用均值**（初版口径，未重标中位）。初版"快 20–35 倍"系中位÷均值，**口径不一致，撤回该倍数**，仅保留"JEV 显著更快"的方向性事实。
- **定性收回**：本轮结论改为"**JEV 接口可用、响应很快，决策效果仍待公平对照**"。冲突案例 DEFER≠胜出（V1.4：识别反证的 CONTINUE_OBSERVE 亦可接受）；持仓减仓≠更正确；JEV 选项=评分+**冻结映射规则**推导（规则全文 jev_mapping_rules_v1.md），代码贡献待三臂对照剥离。

## 未定产品问题（冲突案例）

CONTINUE_OBSERVE 与 DEFER 的产品差异需先定义：若两者都表示"不买、等新证据"，
选项差异可能大于行动差异；若"走弱必须暂缓"本是确定规则，**应由代码执行**
（risk_context_weakening() 已可推导），模型只在其上给理由。待用户裁决后再
评价模型是否"学会体系"。

## 当前工程结论（按用户规则）

DeepSeek 暂作 1.0 默认联调供应商（接入现成+本批成功响应延迟更短）；**不宣布
其决策质量更强**；Kimi 保留为第二适配器。下一步：**小范围、事件触发的双供应商
前瞻影子对照**（两家建议同时记录、不自动故障切换、不影响原提醒），真实记录
再评价。
