# 星币侍从 · 研究 Demo

重启源码版 Stargazer 后，主导航“信息面板”右侧可切换到“星币侍从”。保留原深色 UI 和旧模型页面。

“盘后总结 · 分析选股”用最新本地日线、完整历史重算原冻结 A/B 共性规则，再计算 MA20/BOLL 下轨/前日低点关注区域。按距区域的 ATR 距离排列，**不是模型盈利打分，也不是建议买入价格**。分析隔离运行，最多 15 分钟，失败保留旧件。

“次日到价提醒”默认关闭，开启后持久保存；切出页面仍监控，重启恢复开关和当日去重记录。下一交易日 09:30–11:30、13:00–15:00 每约 60 秒查询现有行情源。价格进入关注区域提醒人工复核，若已经低于区域则单独警示破位；不是买入建议，也不是 S1/S2 分钟信号。

提醒通过原窗口通知通道；顶部微信推送开启并配置有效渠道时，也发送微信。每股每日首次提醒一次，推送失败最多三次（重启不重置次数）；关闭开关不再发起新提醒。服务端推送无法保证网络超时场景的绝对恰好一次。软件关闭/休眠/断网期间不会监控，不回补遗漏的历史触价；请下一交易日保持程序运行。

## 数据与迁移

本轮核实本地日线已更新至 20260930（37 个分片），下一交易日为 20261008。之后每次盘后分析都重新检查日历对应的最近完成日；源数据落后则计划不可用于提醒，不能把旧快照当成次日名单。按钮不运行全市场数据更新器：先按原流程更新 stockdb 和日线镜像，再点击分析。交易日盘中不可生成次日计划，假期可用最近已完成交易日。

日历来自本地 AkShare calendar.json，版本哈希随快照登记；日历到期时拒绝生成名单。报价须为观察日且不超过 90 秒；报价前收与快照收盘偏差超过 0.011 元则标“价格口径不一致”并不提醒（不静默修正除权/复权）。仅价格提醒已实现，实时完整分钟、可执行买点和逐股个性预测仍未验收。

独立输出：桌面程序数据目录 `data/pentacles_demo/snapshot.json`（≤1MiB）和 `monitor.json`（≤2MiB，开关与当日提醒/发送状态）。原子替换；不写旧名单、交易数据库或模型状态。

迁移到监控机体验时，复制更新的程序和此 JSON 到新程序同名数据路径即可展示；不用搬整个研究目录。**2026-10-07 已重打包并更新 `stargazer_desktop/dist/Stargazer.exe`，未迁移或重启监控机。** 现有 dist 配置与数据保持不变；新版 EXE 不嵌入私有 config.yaml 或交易数据库。源码版需同步新 Python 模块和 web 文件；关闭旧程序后再打开新 EXE。

监控机如果需要点击重算，必须具备项目内共性规则/区域引擎、Python/pandas/parquet/AkShare 环境和最新本地日线；不再需要旧冻结成员文件。迁移快照只可在其登记的观察日使用，过期自动拦截。配置示例（写入实际 config.yaml，路径按机器修改）：

```yaml
pentacles_demo:
  project_root: D:/stargazer
  python: D:/stargazer/_dev_venv/Scripts/python.exe
  daily_dir: D:/a股数据/data_daily_parts
```

新页的区域仅是冻结日线构造，**不是已验证的每只股票专属反弹规律**；信息模型、风险模型、LangGraph/JEV 后续另接，不制造它们的输出。
