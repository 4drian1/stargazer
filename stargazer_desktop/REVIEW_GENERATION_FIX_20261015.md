# 星币侍从学习记录生成修复（2026-10-15）

状态：已完成源码修复、离线验收及指定EXE替换；未自动启动生产监控，未调用付费DeepSeek。

## 问题及修复

原版默认2,000输出tokens，让DeepSeek参考旧篇格式生成整篇复盘；返回length或无choice时共用“输出不完整”提示，前端失败后仍保留旧预览，容易误认成当天结果。

现改为：

- `learning_review.py`按完整事实明细生成名单分母、触区/未知数量、相对参考收盘变化统计、典型案例表、七日状态、独立真实成交账本与当日索引。不会让AI重写事实表，不把参考收盘变化称为买入收益或日K收阳。
- AI只接收完整统计和最多6个明确标注的样例，要求600中文字符以内的短判读；服务端对超过1,200字符、无效JSON和空判读拒绝保存，不截取半篇。不再把旧篇数字/完整名单交给AI写长文。
- 新v2草案带report_markdown，预览与确认后追加使用同一程序渲染规则；旧篇/旧草案不重写。学习记录仍须人工确认，幂等追加。
- `deepseek_api.py`细分length、NO_CHOICES、EMPTY_CONTENT及非正常结束；在原usage数据库追加results表，只登记用途/模型/结束原因/token数量/异常类型，不记密钥、提示正文或回复正文。原40调用/120,000tokens日护栏、2,000默认/4,000硬顶、零自动重试保持。
- UI对历史预览标明观察日；非所选日期不允许确认。新生成、换日期、失败均清除旧确认ID；错误后不继续显示上次结果，跨日异步回包不当作当天复盘。

选股规则、持仓风控、报价提醒、七日定义及风险模型接入状态未改。
