## 一、最终系统结构

本图按记录 #3/#4/#9 统一；原线性“Corvus→Pyxis→Astrolabe→Tarot”图不再代表执行顺序。以下是目标功能边界，不代表各模块均已训练通过；不新增独立大模型或强制微服务部署。

  │    ├─ GREEN 盘后 Coverage Watchlist（调整/底部类、下杀关注类分别记录）

  │    └─ 横盘埋伏；打板追龙仅预留接口
  └─ 信息/风险旁路
       ├─ Corvus：事实事件、外围信息、信息影响研究
       ├─ Pyxis / R0：市场、板块、个股及持仓风险
       └─ Astrolabe：信息风险汇总、约束建议、证据引用

机会/入场快照 + 信息/风险快照 + 持仓/组合状态 + 人工冻结计划
                              ↓
                 VERSIONED POLICY ENGINE
                              ↓
         Stargazer Agent 展示/解释/结构化质询 → 人工决定
                              ↓
           真实执行记录 → Position State → Policy 再评估

Runtime 负责调度、持久化、恢复，不决定交易动作。

# 二、当前最优先：修复绿盘低吸的真实收益口径

现在最大的阻碍不是因子数量，而是训练目标与真实交易不一致。

目前应正式作废以下口径：

- `t1_rule_return` 作为真实交易收益；
- `(MFE+5%)/2` 这种用未来最高点构造的收益；
- 固定持有到第五日；
- 将未来五日最高价直接当作可实现卖价；
- 把收益平均摊到五个交易日的伪净值。

这些字段仍可作为辅助标签，但不能进入真实组合账本。

## 阶段0：冻结退出规格

建议建立：

```text
stargazer_ml/v5_hybrid/green_exit_v1/
├─ exit_dyn_spec_v1.md
├─ build_exit_labels.py
├─ portfolio_backtest_v2.py
├─ exit_ablation.py
└─ reports/
```

### 统一交易时序

- T日收盘生成候选；
- T+1按真实开盘或指定可成交价买入；
- A股T+1制度下，买入当天不能卖出；
- 最早卖出日为T+2；
- T+5只是最长观察期限，不是默认卖出日；
- 涨跌停、停牌和无法成交必须延迟到下一可成交时点。

这是不可修改的执行基础。

# 三、EXIT-DYN-v1：第一代动态退出规则

第一版先依赖个股自身价格路径，不能等待 Pyxis。

## 1. 初始风险距离

使用入场前已知的冻结波动率：

\[
ATR_{ref}=\operatorname{median}(ATR14_{T-4},...,ATR14_T)
\]

\[
D_{stop}=\operatorname{clip}
\left(
1.5\times \frac{ATR_{ref}}{Entry},
3\%,6\%
\right)
\]

\[
StopPrice=Entry\times(1-D_{stop})
\]

这是基础参数，不代表1.5一定最优。正式实验可比较1.2、1.5、1.8 ATR，但只能在开发段选一次并冻结。

## 2. 高水位

从买入后开始更新：

\[
HWM_t=\max(Entry,High_1,...,High_t)
\]

\[
PeakRet_t=\frac{HWM_t}{Entry}-1
\]

\[
PeakDrawdown_t=\frac{HWM_t-Price_t}{HWM_t}
\]

只能使用当时已经出现的最高价，禁止引用未来五日最高价。

## 3. 初级反弹退出

当：

\[
PeakRet_t\ge
\max\left(2\%,0.8\times ATR_{ref}/Entry\right)
\]

且从高点回撤达到：

\[
PeakDrawdown_t\ge
\max\left(1\%,0.45\times ATR_{ref}/Entry\right)
\]

视为“反弹开始失败”。

基线实验比较：

- E1-A：全仓退出；
- E1-B：先卖50%，剩余仓位继续跟踪。

不应事先认定分批一定更好，需要账本检验。

## 4. 盈利后的移动止盈

当浮盈达到：

\[
PeakRet_t\ge
\max\left(5\%,1.5\times ATR_{ref}/Entry\right)
\]

启动移动止盈：

\[
TrailDistance=
\max\left(1.5\%,0.75\times ATR_{ref}/Entry\right)
\]

\[
TrailStop_t=HWM_t\times(1-TrailDistance)
\]

价格跌破移动止盈位，在下一合法可成交时点退出。

## 5. 时间衰减

- T+2：给正常反弹空间；
- T+3：若未形成有效反弹，降低继续等待的价值；
- T+4：收紧移动止盈或反弹失败条件；
- T+5：仍未形成有效走势则时间退出。

所以这是“最多观察五日”，不是“死捏五日”。

# 四、两种历史回测口径必须分开

## 2019–2024：日线保守近似

由于缺少完整分钟数据，必须采用保守规则：

- 当日开始前只使用前一日已经形成的高水位；
- 当日同时触及止损和上涨目标时，按止损先发生；
- 不能使用当日新高同时推导当日回撤退出；
- 跳空跌破止损按实际开盘价，而非理想止损价；
- 除权窗口单独隔离；
- 日线结果标记为 `DAILY_APPROX`。

## 2025以后：分钟精确回放

- 按分钟顺序更新高水位；
- 按真实先后判断止损、反弹确认和移动止盈；
- 使用下一分钟成交价或VWAP；
- 处理涨跌停锁死、午间休市和交易成本；
- 标记为 `MINUTE_EXACT`。

两种结果不能混成一个收益表。

# 五、重写真实组合账本

新账本必须包含：

- 现金；
- 持股数量；
- 买卖时间和价格；
- 每笔佣金、印花税和滑点；
- 每日逐仓盯市；
- 20槽真实占用率；
- 同一股票重复买入限制；
- 冷却期；
- 无法成交处理；
- 年末未平仓继续回放至实际退出；
- 正确的最大回撤：

\[
MDD=\min_t\left(\frac{Equity_t}{RunningPeak_t}-1\right)
\]

不能再把退出收益平均分摊到持有日。

## 必须输出的指标

- 年化收益；
- 夏普比率；
- 最大回撤；
- Calmar；
- 胜率；
- 平均盈利、平均亏损；
- 盈亏比；
- 期望收益；
- STOP率；
- 时间退出率；
- 移动止盈率；
- 平均持有时间；
- 资金利用率；
- 成本占毛收益比例；
- 月度收益；
- 板块和个股集中度；
- 去掉最佳月、最佳10笔后的稳健性。

## 模型拆分

### S0：选股头

回答：

> 在符合绿盘战法的股票里，哪只更值得进入观察池？

采用当前较稳的干净特征版本作为起点：

- 训练折中位数填充；
- 训练折拟合MAD标准化；
- 删除常量；
- 暂定同时删除 `impulse_flag` 和 `first_divergence_flag`；
- 市场上下文保留为上下文，不重复充当个股排序因子。

但“同时删除两个标志”只是当前候选结论，需在新退出标签下重新确认，不能直接永久冻结。

### R0：个股风险头

回答：

> 如果买入，这只股票先发生止损、反弹失败或持续走弱的概率多大？

建议预测：

- `p_hard_stop_3d`
- `p_hard_stop_5d`
- `p_failed_rebound`
- `p_timeout_loss`
- `expected_MAE`
- `MAE_q80/q90`

R0可以使用与S0不同的特征表，不再强迫两个头共用一套因子。

### X0：退出头

第一代不直接让模型决定卖出，而是预测：

- 未来1日继续创新高概率；
- 未来1日跌破移动止盈概率；
- 反弹失败概率；
- 未来2日正净收益概率；
- 继续持有的条件EV。

规则负责执行，X0先做建议和影子评分。

## 第6步：入场流诊断与重建闸门

第5步真实账本若证明旧入场流为负，第6步不得按“正常升级”处理，而是一次有硬停止条件的救援实验。目标只回答：**在同一候选池和真实可执行退出下，使用正确目标重新排序，能否提取出成本后正期望子集。**

### 6.0 训练前诊断

- 分别报告 `DAILY_APPROX` 与 `MINUTE_EXACT`，不得把两种精度混成正式收益结论；全期间混合曲线只能作描述。
- 2019—2023逐年、2024开发年、2025分钟精确子集分别报告候选池裸收益、旧F1/F2/F3分位收益、日Rank IC、STOP/MAE、月份和板块集中度。

- 判断是否存在“全池为负但上分位为正”的可学习结构；若所有旧分数分位均无排序，明确记录旧目标失效。

### 6.1 新目标

- 禁止继续用 `best_rule_return`、未来最佳入场日或多退出策略事后取最大值训练。
- S0主目标使用单一、预注册、可执行策略下的净收益/正收益概率；`X0_CONTROL` 作为最简控制目标，X1作为独立挑战者，不按全样本事后表现选择目标。

### 6.2 训练与验证

- 先做规则/线性/LightGBM基线；在传统模型没有稳定增量前不启动深度模型。

# 七、盘后必须生成两类观察池

用户之前明确区分的两类股票，应在系统中物理分开。

## A. `BOTTOM_SETUP`

日线已经调整到位、接近阶段谷底。

主要由：

- 旧绿盘能力；
- S0选股头；
- 支撑/位置；
- 调整质量；
- 板块背景；
- R0风险评分

共同产生。

## B. `INTRADAY_DIP_SETUP`

日线未必已经在谷底，但第二天可能出现可利用的盘中下杀。

主要依据：

- 前期强势；
- ATR波动空间；
- 板块可能继续活跃；
- 个股尚未充分补涨；
- 上方空间；
- 高位耗散风险；
- 次日可能出现分歧。

两类股票不能混成同一个排行榜，因为它们的入场理由和标签不同。

## 盘后候选到次日计划的交付链

两类观察池不能只输出股票代码或冷冰冰的分数。每个候选必须先生成一份**待讨论计划草案**，写入 `stargazer_plan`，但状态保持 `DRAFT`，不能由模型自行冻结。

每份草案至少包含：

```text
setup_type                  BOTTOM_SETUP / INTRADAY_DIP_SETUP
candidate_rank              各自池内排名，不混排
selection_reasons           选中原因和主要正因子
risk_reasons                个股/板块/大盘主要风险
expected_scenario           次日预期路径，不冒充确定预测
entry_zone                  观察价格区域
arm_conditions              进入重点监控的前置条件
trigger_conditions          允许提示买入候选的盘中条件
invalidation_conditions     计划失效条件
initial_stop_reference      基础止损参考
exit_reference              动态止盈/反弹失败/时间退出参考
model_version
evidence_ids
```

盘后流程固定为：

```text
Tarot 生成两类候选
→ 为每只股票生成 DRAFT 计划
→ Stargazer 与用户逐项讨论理由、触发和失效条件
→ 用户采纳/修改/否决
→ 只有人工确认的版本转为 FROZEN
→ 次日状态机只监控 FROZEN 计划
→ 触发、失效、人工决策、成交和反事实回写数据库
```

`INTRADAY_DIP_SETUP` 只表示“次日可能出现值得观察的分歧/下杀”，**不等于下跌即买入**。必须在板块/龙头未明显失效、价格进入预定区域，并出现冻结计划中规定的承接或修复条件后，才能输出 `BUY_CANDIDATE` 提醒。`BOTTOM_SETUP` 同样必须满足自己的入场触发，不能因为日线处于低位就自动推荐买入。

该能力分两次实现：

1. 第8步建立两类观察池时，立即接入 `stargazer_plan` 自动生成结构化 DRAFT，开始真实盘后讨论和数据积累；第一版只使用当时已经验证的 Tarot/S0/R0 信息。
2. 第15步完整 Agent 集成时，再把 Corvus、Pyxis、Astrolabe 的信息风险、结构化质询、相似历史计划检索和自然语言解释补入同一草案流程。后续增强不得改变“模型起草、人工冻结、次日确定性监控”的权责边界。

# 八、LATR：流动性密集区与ATR融合

在基础动态退出、真实账本和干净绿盘基线重跑完成后，进入下一轮绿盘优化。

**LATR 不是等待某个“ATR模型”训练完成后再外挂。** ATR/ATR_ref 是按历史价格确定计算的尺度指标，本身不需要训练。之所以与第一轮基线重训分开，是为了做可归因的增量实验：先证明修复后的 S0/R0 基线在真实退出口径下表现如何，再逐组加入流动性区域、穿透速度、量价修复和板块相对强弱，判断增量来自哪里。

LATR 通过消融后必须回到绿盘体系重新训练相应的 S0/R0/盘中时机头，并刷新两类观察池和计划草案；它最终是绿盘低吸模型的一部分，不是模型完成后的独立插件。若 LATR 未通过，则保留干净基线，不因主观上“技术逻辑合理”而强行接入。

## LATR特征组

### 位置与密集区

- 前低；
- 已确认拐点低点；
- MA20；
- BOLL下轨；
- Anchored VWAP；
- 分钟成交密集区POC/VAL；
- 整数价格；
- 多支撑位聚类强度。

如果多个位置在0.35 ATR内，合并成一个流动性区域。

### 下杀强度

\[
PenetrationATR=
\frac{ZoneLower-CurrentPrice}{ATR_{ref}}
\]

以及：

- 5/15/30分钟下跌速度；
- 开盘15分钟波动占日线ATR比例；
- 是否创新低；
- 二次回踩是否抬高低点；
- 阴线量是否收缩；
- 下跌量/反弹量；
- VWAP收复程度；
- 收针幅度；
- 停留在密集区下方的时间。

### 板块强、个股尚未启动

- 板块相对大盘收益；
- 龙头相对板块收益；
- 个股相对板块收益；
- 板块上涨但个股仍下跌；
- 龙头/中军保持强势；
- 个股距离前高和阻力区；
- 板块走强后个股的延迟反应。

这里不把“跌破流动性位”直接认定为洗盘。模型要区分：

- 流动性扫荡后收回；
- 真破位；
- 高位派发；
- 板块强、个股滞后；
- 板块和个股同步走弱。

## 消融顺序

- L0：修复后的基础模型；
- L1：L0 + ATR位置区域；
- L2：L1 + 穿透深度/速度；
- L3：L2 + 成交量与恢复；
- L4：L3 + 板块强、个股滞后；
- L5：L4 + 高位耗散交互。

不把所有新因子一次塞进去，否则无法归因。

# 九、Pyxis什么时候介入退出

## 现在

只建立字段、日志和接口，保存：

- 大盘风险状态；
- 板块状态；
- 龙头状态；
- 风险发生时间；
- 当时模型输出；
- 后续个股路径；
- 如果按环境提示退出会怎样。

暂不让其改变正式交易。

## Pyxis最小可用后

输出：

```text
p_market_drawdown
p_sector_deterioration
p_leader_failure
p_stock_failure
p_systemic_liquidity_shock
risk_level
evidence_ids
```

然后做三个版本：

- P0：只用个股动态退出；
- P1：个股退出 + Pyxis提示，但不改变交易；
- P2：Pyxis动态收紧退出；
- P3：Pyxis同时控制买入许可与退出。

Pyxis的作用不是重新发明止损，而是调整基础退出参数：

- 风险低：不放宽初始亏损止损，只允许利润运行更久；
- 风险中：保持基准；
- 风险高：收紧移动止盈、缩短等待时间；
- 极端风险：暂停新开仓，已有仓位按下一可成交时点处理。

只有P2/P3跨期稳定优于P0，才进入正式建议。

# 十、Corvus与Pyxis的开发顺序

Corvus采集继续后台运行，不需要每天调参。**闭环完成只代表数据工程可用，不代表信息模型已经训练，更不代表信息具有预测力。** Corvus 与 Pyxis 按以下阶段分别晋级。

## Corvus 信息模型训练路线

### C0：采集与事实层（已完成）

- 新闻/公告原文、来源、哈希和三时间戳落库；
- Qwen 只做事实候选抽取，保留证据与人工复验；
- P0/P1/P2、否定语境、金额/日期证据和中性对照分层。

### C1：最小事件—价格闭环（工程闭环已完成）

- 正式事件、实体链接、重叠事件、30分钟/1日/3日/5日价格反应与标签运行账本进入 SQL；
- 价格标签以 `available_at` 后第一个合法可见/可交易时点起算；
- 当前真实日级标签仍可能为 `CENSORED_TAIL`，工程通过不等于数值标签通过。

### C2：历史回填与可训练数据集（从 C1 后开始；重型回填按文末 2026-09-24 串行排程执行）

- 回填历史公告、政策和新闻，按原始可见时间重建事件；
- 补齐股票/板块/市场映射、市场与板块异常收益、MFE/MAE、冲击—反转—持续性路径；
- 重复转载不扩充样本量，按事件簇/交易日计算有效样本；
- 事件重叠、停牌、除权、数据缺失和尾部截断显式标记；
- 日线更新后自动解封 `CENSORED_TAIL`，每批真实标签做数值重算抽查。

**首次烟雾基线最低条件**：不少于500个已完成、证据完整、实体明确的有效事件，覆盖不少于150个独立交易日；只验证链路和方向，不做事件类别有效性结论。

**正式第一代模型最低条件**：原则上不少于3,000个去重后的完整事件、覆盖至少3个市场年度；需要单独建模的主要事件族原则上不少于200个有效事件。若达不到，则合并事件族或维持规则/描述统计，不强行训练复杂模型。阈值如需因实际分布调整，必须在训练前修改规格并记录理由。

### C3：第一代历史信息影响模型（开发路线第11步正式启动）

先训练可解释基线，不直接上深度模型：

```text
materiality_head       信息后是否出现显著异常波动
direction_head         1日/3日/5日 UP / FLAT / DOWN 概率
reflexivity_head       初始冲击后是否收复、反转或继续扩散
persistence_head       信息影响是短暂、持续还是已被提前定价
```

- 输入只使用 `available_at` 时已经可见的信息、历史市场状态和事件事实；
- 先比较简单规则、正则化逻辑回归和 LightGBM；复杂模型必须证明有独立增量；
- Qwen 输出是事实特征与证据，不作为“利好/利空真值”；
- 2019—2025历史结果属于开发证据，已经参与过假设形成的年份不得重新包装成纯锁箱。

### C4：Corvus 影子评分与前瞻校准

- 输出事件重要性、方向、反身性和持续性概率，以及校准度、缺失警告和 `evidence_ids`；
- 只写数据库、展示和归因，不直接允许/禁止交易；
- 代码冻结后的新前瞻期用于否定、校准和晋级，不按每日结果追着改参数。

### C5：接入 Pyxis

- Corvus 只输出结构化信息概率与证据；
- Pyxis 负责判断这些信息在当前市场、板块、个股和持仓状态下是否构成风险；
- Corvus 不直接发买卖指令。

## Pyxis 风险模型训练路线

### Y0：冻结风险对象与标签（第5步真实20槽账本完成后开始）

Pyxis 不能先凭指数涨跌定义风险，必须由真实可执行账本和候选池定义：

```text
market_risk_label      未来1/3/5日候选池或组合左尾风险
sector_risk_label      板块/梯队/龙头走弱后的条件损失
stock_risk_label       个股STOP、MAE、失效和流动性风险
position_risk_label    已持仓继续持有相对退出的条件风险
intraday_risk_label    盘中风险突变、炸板、流动性与相关性扩散
```

必须区分“未来波动很大”和“应该暂停买入”，不能再次把短期波动警告当成持续亏损标签。

### Y0.5：历史行为表征层——大盘共性、板块状态与个股个性

在正式训练 Y1 风险头之前，先建立可复用的历史行为表征层。该层的目标不是直接给出买卖指令，而是回答三个基础问题：

```text
1. 当前大盘处于历史上哪一类状态，类似状态过去的风险分布怎样？
2. 当前板块相对大盘处于什么状态，板块—龙头生态是否异常？
3. 当前个股相对自己的历史行为基线是否异常？
```

这一层必须严格使用决策时点以前的数据滚动构造，禁止用全历史统计量回填过去样本。所有画像和 Regime 特征都必须带 `as_of_time / feature_version / lookback_window`，保证历史回放、训练和线上推理使用同一口径。

#### Y0.5-A：Market Regime——学习大盘历年共性

目标：从多个市场年度中学习可重复出现的市场状态，而不是用“指数涨跌多少”直接等价为风险。

第一代至少保存：

```text
market_trend_state
market_volatility_state
market_liquidity_state
market_breadth_state
market_correlation_state
market_momentum_state
market_leader_state
market_sector_rotation_state

market_regime_id
market_regime_embedding       # 深度模型阶段可选
historical_regime_similarity
```

基础输入可包括：

- 主要指数 1/3/5/20 日收益、趋势和回撤；
- 实现波动率、ATR、跳空和尾部波动；
- 全市场上涨/下跌家数、涨跌停数量、炸板率；
- 全市场成交额及其历史分位、流动性收缩/扩张；
- 大盘/小盘、价值/成长、权重/题材相对强弱；
- 板块收益离散度、板块集中度和轮动速度；
- 个股相关性、同步下跌比例和系统性共振程度；
- 龙头/高位股持续性、连板生态和高位亏钱效应；
- 候选池自身的横截面收益、MAE、STOP率和左尾分布。

Market Regime 的训练目标不是人为固定“牛/熊/震荡”标签，而是先形成连续状态表征，再由 Y1 的 `market_risk_label` 学习不同历史状态对应的真实候选池/组合左尾风险。

必须报告：

- 相似历史 Regime 的后续 1/3/5 日候选池收益和左尾分布；
- Regime 样本量和年份覆盖；
- 是否过度依赖单一年份；
- 时间外 Regime 表征稳定性；
- 加入 Regime 后相对简单指数/波动率规则是否有独立增量。

#### Y0.5-B：Sector Regime——学习板块自己的历史状态

目标：区分“板块今天弱”和“板块相对它自己的历史与当前大盘状态异常地弱”。

至少保存：

```text
sector_beta_market
sector_relative_strength_1d_3d_5d
sector_breadth
sector_turnover_state
sector_leader_concentration
sector_rotation_speed
sector_drawdown_state
sector_volatility_state
sector_abnormal_return
sector_regime_id
sector_regime_similarity
```

其中 `sector_abnormal_return` 应尽量表示：

```text
实际板块表现
-
在当前 Market Regime 下该板块历史上通常的条件表现
```

板块状态必须和龙头/中军生态联合建模，避免只用板块指数涨跌判断强弱。

#### Y0.5-C：Stock Behavioral Profile——学习个股长期个性

每只股票建立滚动更新的行为画像，用于描述“这只股票平时是什么性格”，而不是让模型只看跨股票统一阈值。

2026-09-28 补充：GREEN 买点研究先实现该画像的轻量子集（历史下杀幅度、修复概率、量价承接、流动性区域及样本置信度），不必等完整 Pyxis 长期个性模型完成；共享字段仍须保持同一口径。按记录 #10，只使用当时已经闭环的历史事件，样本不足回退到共性估计或等待，不单独为每只股票训练模型。

第一代建议建立 `stock_behavior_profile`，至少包含：

```text
stock_beta_market_60d
stock_beta_sector_60d
idio_vol_20d
idio_vol_60d

atr_pct_median_60d
atr_pct_q80_60d

gap_mean_60d
gap_vol_60d

open_dip_mean_60d
open_dip_q80_60d
open_dip_stock_percentile_60d
open_dip_stock_zscore_60d

recovery_after_dip_rate
recovery_speed_median
support_reclaim_rate
vwap_reclaim_rate
break_support_failure_rate
higher_second_low_success_rate

turnover_median_60d
turnover_q80_60d
volume_elasticity

sector_follow_beta
sector_lag_tendency
drawdown_recovery_speed

historical_MAE_profile
historical_MFE_profile
```

核心原则：同一个绝对行为必须同时保留三种尺度。以 `OpenDipATR` 为例：

```text
open_dip_atr                    # 绝对状态
open_dip_market_percentile      # 相对当日横截面
open_dip_stock_percentile_60d   # 相对个股自身历史
open_dip_stock_zscore_60d       # 相对个股自身分布
open_dip_regime_percentile      # 相对当前 Market Regime 的条件分布
```

这样模型才能区分：同样 `OpenDipATR=0.20`，对一只平时波动很大的股票可能只是正常噪音，对一只平时很稳的股票可能已经是异常风险。

个股画像第一代必须优先使用可解释、可滚动更新的行为统计特征；`symbol_id → embedding` 只能作为后续 challenger，不能取代行为画像，也不能让模型通过记忆股票代码获得虚假时间外性能。

#### Y0.5-D：三层历史上下文的共享方式

历史表征层最终形成：

```text
Market Regime
    ↓
Sector Regime
    ↓
Stock Behavioral Profile
```

职责边界：

- Tarot/S0/Timing/R0 可以读取部分 Stock Behavioral Profile，使机会模型知道“这次行为对这只股票自己是否异常”；
- Pyxis 负责把 Market Regime、Sector Regime、Stock Behavioral Profile、持仓状态和 Corvus 信息风险结合起来，判断当前环境是否正在放大损失概率；
- 个股行为画像不替代 R0，Market/Sector Regime 也不直接替代买点模型；机会与风险继续保持双轴。

建议新增或冻结以下数据表：

```text
market_regime_snapshot
sector_regime_snapshot
stock_behavior_profile
stock_behavior_snapshot
regime_similarity_history
```

其中 Profile 表保存滚动历史画像，Snapshot 表保存决策时点可见的实际特征版本，禁止收盘后回写过去快照。

#### Y0.5 晋级条件

只有满足以下条件，历史行为表征层才允许进入 Y1 正式风险训练：

- 所有特征严格 point-in-time，可从历史时点复现；
- Market Regime 覆盖多个市场年度，不由单一年份主导；
- Sector Regime 有足够板块和不同市场状态覆盖；
- Stock Behavioral Profile 对低历史样本股票有缺失/冷启动处理，不能使用未来补齐；
- 加入历史表征后，相对简单市场/板块/个股基线至少在风险分层、Brier、PR-AUC或真实左尾识别中出现可复验增量；
- 去掉某一年、某一板块或少数高频股票后结论不反转；
- 深度 embedding 若使用，必须相对可解释行为画像证明独立增量。

若 Y0.5 不通过，则 Y1 继续使用简单可解释上下文，不因为“历史模式听起来合理”而强行接入。

### Y1：分头基线训练（开发路线第12步）

- 大盘/候选池风险头：显式使用 Market Regime，并与简单指数/波动率基线做有/无历史表征消融；
- 板块—龙头生态风险头：显式使用 Sector Regime、板块异常收益和龙头生态状态；
- 个股位置、流动性和高位耗散风险头：显式加入 Stock Behavioral Profile，判断当前行为相对个股自身历史是否异常；
- 持仓与盘中风险头：同时使用当前价格路径、持仓状态、Market/Sector Regime 与个股行为偏离；
- Corvus 信息风险作为独立特征组做有/无消融；
- 历史表征层同样必须做有/无消融，禁止把 Regime/Profile 的复杂度直接视为有效性。

每个头先与简单规则、逻辑回归比较，再决定是否使用 LightGBM/Transformer；不预设深度模型一定更优。

### Y2：校准与风险融合

输出：

```text
p_market_drawdown
p_sector_deterioration
p_leader_failure
p_stock_failure
p_position_exit_risk
p_systemic_liquidity_shock
risk_level
evidence_ids
```

概率必须在训练外时间段校准，风险等级由冻结阈值产生，不使用当期收益反向调档。

### Y3：Astrolabe 增量实验（开发路线第13步）

- P0：只有个股动态退出；
- P1：加入 Pyxis 提示但不改变交易；
- P2：Pyxis 调节买入许可和退出参数；
- P3：Pyxis + Corvus 信息交互。

只有高风险组损失率单调上升、概率指标优于简单基线、放行池收益风险不恶化，并且 P2/P3 在时间外样本稳定优于 P0，Pyxis 才能影响正式建议。

### Y4：盘前/盘中/持仓影子运行

- 盘前提供市场和板块风险背景；
- 盘中监控龙头炸板、板块扩散、流动性突变和信息冲击；
- 持仓层提示收紧、减仓或退出候选，但仍由人工决定；
- 前瞻日志用于周期性离线复训，不进行每日在线学习。

# 十一、数据库什么时候接

完整数据库迁移不是当前退出实验的前置条件，但**最小交易计划/人工决策日志不能等到 Agent 最后接入时才开始**。否则模型没有“盘前原始观点→盘中修改→实际执行→事后结果”的可训练链路，会丢失数月关键样本。

因此数据库分两步：

1. Corvus 最小信息闭环完成后，立即建立最小计划日志层，只记录计划、触发条件、模型建议、人工决策和结果归因；不改变模型权重、不自动下单。
2. Agent 集成前再完成全量 SQL 状态层和跨服务迁移。

建议：

- 大型历史行情继续使用 Parquet；
- SQL保存状态、模型输出、人工决策和审计链；
- 单机阶段使用 SQLite WAL；
- 多电脑或多进程同时写入时再迁移 PostgreSQL。

核心表：

```text
model_prediction
market_risk_snapshot
sector_risk_snapshot
position_risk_snapshot
trade_plan
plan_candidate
trigger_rule
watchlist_state
human_decision
execution_log
outcome_attribution
hypothesis_registry
dialogue_evidence
```

最小计划日志必须从启用之日起保存：

```text
plan_session
plan_candidate
trigger_rule
model_recommendation
human_decision
execution_log
outcome_attribution
dialogue_evidence
```

盘前计划一经确认即写入不可变版本；盘中修改另建新版本并保留时间戳，禁止收盘后回写美化盘前判断。

禁止继续用自由文本JSON作为唯一记录，但模型解释性JSON可以作为SQL字段中的附加证据保存。

# 十二、Stargazer Agent的决策流程

不要让两个LLM自由争论。使用结构化协议：

1. Tarot输出候选与因子证据；
2. Pyxis提出风险质询；
3. Tarot只能针对指定风险逐项回应；
4. Astrolabe按冻结规则合成；
5. LLM把结构化结果翻译成人话；
6. 人工决定买入、等待或否决；
7. 决策及理由落库；
8. 事后归因，不直接在线修改模型。

最终动作限定为：

```text
REJECT
WATCH
ARMED
BUY_CANDIDATE
HOLD
REDUCE
EXIT_CANDIDATE
```

模型只提供建议，不自动下单。

## 从交易计划对话中学习的分层

对话内容必须拆成四类，不能直接整段拿去微调：

1. **用户硬约束/风险偏好**：如最大单票仓位、禁止追高、最大可接受回撤。经用户确认后进入配置层，不需要训练。
2. **次日交易计划**：候选、触发条件、失效条件、观察证据和优先级。结构化并冻结版本，次日由状态机监控。
3. **市场假设**：如“板块强而个股滞涨可能出现低吸机会”。进入假设注册表，必须回测或前瞻验证后才能进入模型。
4. **人工偏好与真实结果**：同时保存“用户更喜欢哪个方案”和“哪个方案事后经济结果更好”，两者不得混为一个标签。

近期只做结构化抽取、检索相似计划、触发提醒和事后归因；禁止每日在线微调、禁止由聊天直接改模型权重。积累足够完整样本后，优先训练轻量排序/偏好模型；只有在样本量、稳定仿真和独立锁箱均满足时，才评估 DPO 或受约束策略学习，RL 不是默认路线。

## 交易计划对话学习的渐进路线

### DL0：数据契约与不可变日志

- 将盘前对话抽取为：市场判断、候选、计划类型、触发条件、失效条件、目标/止损参考、风险依据、置信度和证据。
- 用户确认后冻结 `plan_version`；盘中修改只能追加新版本，不能覆盖盘前原文。
- 同时保存模型原建议、人工决策、实际成交和未执行反事实。
- 本阶段不学习，只保证未来有可信样本。

**晋级条件**：字段可唯一解析；时间戳和版本不可回写；同一计划可从原对话复现；触发、失效、成交和结果能够关联。

### DL1：计划助手与确定性提醒

- LLM 负责把对话转为待确认计划，不自行补造价格或条件。
- 次日由确定性状态机监控 `WATCH→ARMED→TRIGGERED→INVALIDATED`。
- 命中条件时提醒用户，不自动下单、不修改模型。

**晋级条件**：历史重放中触发时点无未来信息；漏报、误报和重复提醒可统计；所有提醒能指回冻结计划与证据。

### DL2：相似历史计划检索与风格档案

- 从 SQL 结构化字段和对话证据建立检索索引；向量检索只负责找相似案例，不直接决定买卖。
- 风格档案只保存经用户确认的稳定偏好和硬约束；临时观点不自动升级为长期风格。
- 生成计划时并列展示相似案例当时的市场背景、计划和真实结果，避免只检索成功案例。

**晋级条件**：检索严格使用决策时点以前的数据；成功/失败/未执行案例均覆盖；人工确认计划的一致性改善且没有增加风险违规。

### DL3：归因与假设学习

- 区分模型建议、用户盘前计划、盘中修改、实际执行和不操作反事实。
- 按理由统计 Human Alpha、Override Regret、触发质量和失效条件有效性。
- 从对话提取的新观点进入 `hypothesis_registry`，经回测或前瞻验证后才允许转为 Tarot/Pyxis 特征。

**晋级条件**：至少积累一个完整前瞻观察周期；缺失记录、中途改写和事后补录率达到验收要求；增量结论不依赖少数月份、股票或单一板块。

### DL4：轻量双目标学习

- 先训练两个彼此独立的轻量模型：`human_preference_score` 预测用户更可能接受什么；`realized_quality_score` 预测方案的真实收益风险质量。
- 两个分数并列输出，由 Astrolabe 按冻结规则使用；不得把“用户喜欢”直接等同于“更赚钱”。
- 优先使用可解释的排序模型/分类模型，不直接训练端到端交易 Agent。

**晋级条件**：按时间切分的未见数据上，偏好预测稳定；经济质量模型相对冻结基线有增量；组合收益、回撤和人工违规率不恶化。

### DL5：可选的 LLM 偏好微调

- 只有积累足够多、明确、互不矛盾且可审计的方案偏好对后，才评估 SFT/DPO。
- 微调只改善提问方式、计划组织、解释和方案呈现，不获得自动下单权限，也不替代 Tarot/Pyxis 的数值输出。
- 每次模型升级固定训练数据快照、版本和独立验证集。

**晋级条件**：盲评中计划质量和一致性提升；事实编造率、风险遗漏率不升；不会改变冻结的交易约束或伪造证据。

### DL6：可选的受约束策略学习

- 只有在长期完整轨迹、可信反事实、稳定仿真器和新锁箱均具备时，才研究 contextual bandit 或受约束策略学习。
- 仓位上限、禁止事项和风险纪律保持硬约束，不能仅作为可被收益抵消的奖励惩罚。
- RL 不是项目必经阶段；若轻量模型与人机决策已经满足目标，则不实施。

**最终目标**：Stargazer 能基于 Tarot 候选、Pyxis 风险、Corvus 信息和用户冻结计划进行结构化讨论与次日实时提醒；能够解释采纳/否决原因、检索相似历史、量化人工增量，并在独立验证通过后逐步学习稳定偏好与有效决策模式。最终决策权仍属于用户，任何学习阶段都不得绕过可复现回测、风险闸门和人工确认。

# 十三、验收闸门

## 工程闸门

- 零未来数据；
- T+1交易限制正确；
- 同bar冲突按悲观顺序；
- 涨跌停不可成交正确；
- 除权和价格尺度正确；
- 标签、回测和线上推理使用同一特征版本；
- 每个预测可追溯到数据快照和模型版本。

## 模型闸门

- 日Rank IC跨期方向稳定；
- 风险分层单调；
- 高风险组真实损失率更高；
- 放行池收益不能恶化；
- Brier、PR-AUC至少一项严格改善且另一项不显著恶化；
- 不依赖单月、单板块或少数交易；
- 3个随机种子至少2个同向；
- 20槽真实组合优于规则基线；
- 成本后仍有正期望。

## 上线闸门

- 先影子运行；
- 不改变买卖建议；
- 连续记录至少20–40个交易日；
- 再做小资金人工执行；
- 至少60个交易日完整数据后，才考虑从人工对话中提炼新规则。

## 2026-09-23 路线变更记录 #4：Orchestration/Runtime Layer 合同冻结（实现选型推迟）

### 定位
- 正式架构只冻结**功能层**，不冻结第三方框架：`MODEL/SIGNAL LAYER`（Opportunity/Entry State/Position State/R0/Pyxis/Corvus）→ `ORCHESTRATION / RUNTIME LAYER` → `VERSIONED POLICY ENGINE` → `Human Decision`。
- **ORCHESTRATION ≠ POLICY（第四条硬边界）**：Orchestration 只管"谁什么时候运行、状态去哪"；Policy 只管"冻结输入→什么动作"。换任何 workflow 引擎（LangGraph/自研 runner/Temporal）都不得改变 Policy 结果。Policy 逻辑不得住在 Orchestration 里（"顺便算 policy_action"禁止）。
- 实现选型=DEFERRED：LangGraph 是 IMPLEMENTATION_CANDIDATE，不是必装依赖。Runtime 层冻结的是能力合同：parallel fan-out / state persistence / resume-recovery / human interrupt / snapshot 汇总 / lifecycle routing / audit trail。到 SHADOW_RUNTIME_V1 按 #9.6 的需求与输入就绪门立项，再 benchmark（LangGraph vs thin custom runner + plan_db/状态机）；模型数量本身不构成立项依据。

### 快照契约（现在冻结，代码接口已落地 `stargazer_ml/v5_hybrid/opportunity_v2/contracts/snapshot_contracts.py`）

- 这里“已落地”指框架无关的数据类/输入输出契约；**不代表所有模型已实现适配器，也不代表 LangGraph 图、持久化和恢复流程已接好**。接口字段后续按 #9.3 升级，禁止因此声称接入时完全无需改动。
- 五类世界状态快照：`OpportunitySnapshot / EntryStateSnapshot / RiskSnapshot / ContextSnapshot / PositionStateSnapshot` + 一个决策对象 `PolicyDecision`（**与快照不并列**：五个快照是状态，PolicyDecision 是确定性函数的结果）。
- 全部强制全局头：`snapshot_id / schema_version / frozen_artifact_ref / symbol / asof_ts（最晚用到的信息时刻）/ created_ts（实际生成时刻）`；`frozen_artifact_ref` 用 `artifact_type:artifact_version:hash` 三元组（非文件路径），防同名误认。
- `PolicyDecision` 记录：`policy_version / input_snapshot_ids / action / reason_codes / requires_human_review / created_ts`。

### 三条硬纪律
1. **POLICY_DETERMINISM_CONTRACT**：同输入+同 policy_version ⇒ 同输出。policy_action/reason_codes 必须可复现、可审计。
2. **Agent 对话 LLM = presentation/explanation sidecar**：可翻译 reason_code、生成摘要和待人工确认的计划草案；**禁止**直接修改 score/决定 BUY-WAIT-REJECT/调仓/退出或代替人工 override。自由文本及未经确认的 LLM 输出不得直接进入确定性决策节点。Corvus 的证据约束事实抽取、人工确认后版本化的结构化计划是独立受控入口，不等于放开“文本→parser→signal”捷径（见 #9.4）。
3. **SHADOW_RUNTIME_V1 首版本机旁路**：读取监控/历史产生的 Snapshot→调模型→跑 Policy→生成 Shadow Decision；NO order / NO production control / 不依赖监控进程。当前监控机精简 exe 生产路径**禁止**引入 LangGraph/langchain-core/checkpoint DB/async runtime。验证（稳定性/延迟/恢复/一致性/资源/异常恢复）通过后才谈部署。

### 顺序不变
STEP1（诊断，进行中）→ O2A → O3 → 至少一个 Opportunity Source 通过 → GREEN-v2.2 Intraday/Entry/Exit；**同时** R0/Pyxis/Corvus 继续数据/标签/Snapshot/Shadow 建设（Predict→Snapshot 接口形态）；SHADOW_RUNTIME_V1 届时再评估 LangGraph vs thin runner。现在各模块的接口义务：以纯函数形态暴露 `predict/infer/evaluate(snapshot…)→Snapshot`，不自行操作库、不自行决定交易流程。

### STEP1 结果登记（2026-09-23，green_v22_candidate_quality/report_v1.md）

## 2026-09-23 路线变更记录 #5：Memory / Personalization Layer 设计冻结（只设计+记日志，不做系统）

### 核心思想（永久）
**模型的长期记忆存在数据库里，不存在 prompt 里；prompt 每天只从长期记忆取与今日最相关的一小部分。** 禁止"把每天所有聊天塞进 prompt"——历史可无限增长，每次上下文必须有限。
```
完整历史 → 持久化存储 → 结构化提取/汇总 → 按当前任务检索少量相关记忆 → 当天上下文 → 生成交易计划
```

### 五层记忆结构
1. **Raw Event Log**：不可变事实层（plan/snapshot/policy decision/人工最终决定/修改理由/成交/结果/复盘），量大但永不过 LLM。
2. **TraderProfileSnapshot**：交易风格载体（entry/risk/position preferences + behavioral_patterns），每日上下文只带当前版本（几 KB），v17→v18 版本化演进；**不因一句话改 Profile，要证据累计+统计确认**。
3. **Daily/Weekly/Monthly Summary**：压缩链（100 万字聊天 → 1000 daily → 150 weekly → 30 monthly → 1 Profile）。
4. **Episodic Memory**：代表性交易案例（context/opportunity/entry/系统动作/用户动作/理由/outcome/lesson），当日按相似度检索 3-5 个送入，不送全部历史。
5. **Recent Working Memory**：当日计划/持仓/盘中已发生/当前机会，日终压成 DailySummary。

### 两条铁律
- **Preference ≠ Performance 分开学习**："用户喜欢早买"（UserPreference）不得自动推导"早买更赚钱"（Performance）；两套模型并列输出（如："你在此类场景倾向提前介入；但历史 38 笔提前介入 MAE 明显更高，R0 建议等待"）。最终可形成三 Profile：TraderPreferenceProfile / TraderPerformanceProfile / SystemPerformanceProfile。
- **个性化不得污染确定性 Policy**：未来 Profile 若参与 Policy，只能经**人工确认+明确字段+冻结版本+明确规则**（如 risk_tolerance_level=2 经 policy_v5 规则引用）；**禁止** LLM 读自由文本/近期聊天悄悄改行为。Agent 的未确认输出不得作为决策输入；确认后的计划/偏好通过受控配置接口进入，聊天原文只作证据与后续离线研究，不在线改权重（见 #9.4）。

### 阶段划分（M0-M3，不拖走当前主线）
- **M0（现在）**：只定义 schema + 不可变日志。四个基础对象即刻开始落库：`DecisionEvent`（decision_id/trade_date/opportunity_id/policy_decision_id/system_action/human_action/override_flag/override_reason_code/human_comment/execution_result/outcome_ref + 全局头）、DailySessionSummary、TraderProfileSnapshot、TradeEpisode。全部沿用 Snapshot 契约全局头（schema_version/frozen_artifact_ref/created_ts/asof_ts）。成本极低，保证从今天起数据不丢。
- **M1（SHADOW_RUNTIME_V1 时）**：Daily summaries / Episode memory / bounded retrieval。
- **M2（前瞻数据积累后）**：TraderProfile learning / Preference vs Performance 分离建模。
- **M3（成熟系统）**：个性化计划 / override learning / 行为归因。

### 8.3 模型优化方式：先小基线，后有限搜索

1. **职责不混**：Opportunity 研究“是否形成有增量的机会”；GREEN 研究符合战法后的时机/风险。现有 GREEN 冻结模型不因实验自动替换，Corvus/Pyxis 总架构不变。逻辑回归是可解释概率基线，贝叶斯优化是超参数搜索方法，不是额外的选股信号，也不替代数据/标签修复。
2. **新增到尚未开跑的实验预注册，不追认历史**：Gate1C-C6 过门后，首个盘中假设在看结果前写明同一候选/同一分钟风险集上的常量概率、简单规则、L2 正则逻辑回归对照；可预注册极少量有依据的交互。只在开发段比较少量固定正则强度，缺失填充/标准化/特征筛选均在各训练折拟合。样本不足先描述，不承诺 LR 能创造盈利。
3. **标签与收益一致**：机会分类目标由冻结可执行规则产生，例如固定 H3/H5 主次关系下的成本后收益正负，不能用事后最高价/最佳入场日；风险分类对应实际损失/尾部事件，两头独立评估。`p_up` 不等于净 EV，`1-p_stop` 不等于胜率；仍检查实际单笔净收益、同分钟增量、覆盖/容量和真钱账本。若构造三状态概率，采用同路径互斥标签和归一多分类，不拼三个未约束概率。
4. **不再把裸池负均值当数学不可能**：裸池平均亏损不排除存在正的条件子集。新假设可事前注册一次有预算的简单条件学习检验，与机制/对照结果一起裁决；这不更改旧 O1/O2/O3/O5 FAIL，不允许看过失败结果再给旧实验临时加 LR、切片或搜参。正均值也不自动证明条件排序有效。
5. **贝叶斯调参后置、串行**：仅在干净基线有跨时间开发折可复核增量、且未触发原硬否决后启用。每次预注册一个模型家族与固定搜索空间，默认最多 30 trials、n_jobs=1；不同时搜索候选定义、标签、退出规则、持有期或板块名单。LR 优先少量固定参数比较，树模型再考虑 TPE 等有限搜索；不得“失败就加预算”或挑最有利随机种子。
6. **验证结构**：嵌套前向时间划分，内层选超参数/校准/阈值，外层只评估；按 `label_end` 清除跨界重叠，依冻结持有期设隔离间隔，同一事件各决策点/目标档不拆折。分类内层主目标事先选择 log loss 或 Brier，辅看 PR-AUC 与校准；最终仍以原冻结经济/风险门验收，不优化单一年化峰值。校准模型与阈值绑定同版本评分器，禁止 OOF 阈值直接套尺度已变的全量 refit。
7. **样本与证据边界**：分钟行数不是独立样本数；同时报独立事件、股票、交易日与月份，区间按交易日/连续时间块估计，重叠持有窗口保留相关性。2025/2026 已被反复观察的区间只作开发/压力描述，不重新命名纯样本外；确认需冻结后的未见前瞻数据。只允许轻量基线的先验学习，不允许反向时间折参与部署模型选择。

方法参考（采用原则，不照搬随机交叉验证示例）：[正则化逻辑回归](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html)、[嵌套选择与外层评估](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html)、[Optuna 搜索与剪枝](https://optuna.readthedocs.io/en/stable/tutorial/10_key_features/003_efficient_optimization_algorithms.html)。

- 机会与风险在**逻辑上并行输入** Policy；不要求两条重训练任务物理并行。Corvus 可给 Pyxis 提供事实，但风险尚未知不应阻止候选被记录/观察；建议权限按当前影子合同限制。
- Watchlist 外发现仍受 GREEN_ELIGIBLE_UNIVERSE 与质量边界约束，不是无限全市场扫描。多来源用稳定 opportunity/event id 去重，保留 source_modes；同源 ATR/修复/板块信号需做重叠归因，不能简单投票或相乘概率。

- 持仓/组合接口保留实际成本、数量、可卖数量、行业/共同风险敞口；组合约束先用简单确定性规则，无需再建一个“大总模型”。横盘埋伏、未来打板分支复用这套边界，各自保留标签/战法版本，不迫使所有策略使用同一预测头。

### 9.4 对话计划与信息抽取的受控入口

- **对话路径**：交流/检索→结构化 DRAFT→字段/执行条件校验→人工确认→不可变计划版本→确定性监控。只有确认后的结构化规则/偏好可作为 Policy 输入；聊天文本、未经确认的修改与 LLM 自行 override 都不得进入交易动作。

- 交流、修改、采纳、拒绝、未触发、数据缺失、实际成交和反事实分开记录；风格学习继续后置离线验证，不因为用户认同计划就把它标成盈利正例，不每日在线改模型权重。仍无自动下单、无自动冻结、无 DPO/RL 提前立项。

### 9.6 LangGraph 预留现状、延期范围与启用时机（同日补充）

- **已核实的预留**：`contracts/snapshot_contracts.py` 已定义 SnapshotHeader、Opportunity/EntryState/Risk/Context/PositionState 五类快照和 PolicyDecision，不依赖 LangGraph；路线要求模块以 `predict/infer/evaluate(snapshot)→Snapshot` 暴露能力。当前状态 = `INTERFACE_CONTRACT_EXISTS / MODULE_ADAPTERS_NOT_FULLY_VERIFIED / RUNTIME_SELECTION_DEFERRED`，不是“LangGraph 已接入”。
- **现在不做**：不为 C5/C6 安装框架、编写 Agent 对话循环、搭图或改监控 exe；只维护可序列化契约、时间/版本/错误语义和独立 Policy。GREEN 仍是冻结影子能力，Corvus 仍需历史标签/训练验收，二者状态不因接口预留而升级。
- **不是两个模型硬门槛**：一个模型的长期人工计划确认/恢复流程也可能需要编排；多个简单评分器仍可由轻量 runner 完成。是否用 LangGraph 取决于跨步骤状态、人工中断、失败恢复和可观测需求，而非模型计数。
- **本项目默认评估节点**：先稳定 GREEN/Gate1C-C6 快照与回放，再按串行路线推进 Corvus。当 GREEN 与 Corvus 的正式事件或评分能提供稳定、可追溯的输入，且确实要运行“候选→信息风险汇总→计划草案→人工确认→提醒/复盘”的旁路流程时，立项 SHADOW_RUNTIME_V1 选型。Corvus 事件闭环可作为信息输入，不强求先拥有第二个训练好的预测模型；但未知/未经验证的评分仍不得改变正式交易建议。
- **影子对比验收**：同一批快照分别交给 thin runner 与 LangGraph 原型，比较 Policy 的 action/reason_codes 一致性、断点恢复、人工等待/超时、重复事件与重复提醒、重启后版本锁定、延迟及 CPU/内存/磁盘成本。恢复时校验输入是否过期，旧计划确认不能直接执行已经失效的条件；冻结计划/成交/审计 SQL 仍是业务事实源，图 checkpoint 不是替代账本。
- **只迁移调度，不迁移决策权**：LangGraph 若胜出，只负责任务编排和状态恢复；不改 Policy、不自动批准计划、不解除人工终审、不触发重训或扩大自动交易权限。Runtime 的轻量并发不解除“重型回填/构建/长训练串行”。选型没有明确收益时继续 thin runner，不为使用框架而使用框架；是否部署到监控机另过资源和稳定性验收。

技术依据：[LangGraph 官方定位](https://docs.langchain.com/oss/python/langgraph/overview)与[持久化/恢复说明](https://docs.langchain.com/oss/python/langgraph/persistence)提供的是有状态工作流能力，不是“多模型才能使用”的前提。本节只登记采用条件，不安装或实现该框架。

### 10.2 共性观察名单：两类分别定义、允许重叠但不重复持仓

- 强势首次分歧类（对齐 DIP_SETUP）：先有可因果识别的强势背景与短期首次放量分歧，随后至少两天连续下跌且缩量，接近日 K BOLL 中轨。红绿穿插不满足本轮连续下跌定义；K 线实体红绿与相对前收涨跌分别记录，不能混用。此类只是值得观察，不等于分歧必将修复。
- 调整/底部类（对齐 BOTTOM_SETUP）：此前有方向性、持续下跌，最近至少三天下跌或横盘；量能已经处于低位且变化趋稳，RSI<35，接近日 K BOLL 下轨。横盘、低 RSI、贴近下轨均不能单独证明见底；保留继续下跌和未修复样本。
- “低量”与“稳量”分开量化：低量使用近期成交量/历史成交量基准及个股历史分位；稳量使用近期量能离散度与趋势斜率。高量但稳定不算低位稳量。原始成交量、成交额、可比换手及单位/复权质量同时记录。
- 接近 BOLL 使用有符号距离及 ATR 归一距离；记录轨道斜率、历史跌幅/价位和首次分歧的历史定位，而不是只输出布尔通过。先保留连续特征，观察池规则与模型买入条件分离。
- 实现前预注册尚未确定的参数：强势/长期下跌回看期、“首次”的重置条件、横盘容忍度、量能短长窗与低位阈值、RSI/BOLL 周期和轨道距离。用户给出的至少 2 天/3 天、RSI<35 与低位稳量方向保留；其余数值不根据测试收益临时补定。
- 两类名单各带 setup_type、形成时间、证据、数据质量和失效条件。允许同股同时有两类证据，但计划库/账户按股票去重；不要求先有板块启动或风险放行才发现观察候选。

### 10.3 个性买点：条件历史分布，不是记住某个必涨价格

- 在候选形成后，读取该股历史已完成 5/15 分钟 K 线及可比下杀事件。历史事件按预先冻结规则识别，纳入失败/未反弹样本，禁止只搜历史成功收针。
- 估计历史下杀 ATR/LATR 深度分位、流动性区域距离、下杀速度、量能收缩/承接、低点结构、VWAP 修复及随后 3/5 日可执行收益/风险。优先匹配形态、时段与背景，避免把早盘与下午、高位分歧与长期低位混为一谈。
- 输出买入关注区间、修复/失败概率、独立事件数与置信度、触发/等待/失效条件；不输出“到了某个价就一定反弹”。区域由当时已知锚点与历史分布映射，不能引用未来最低/最高点。
- 个股样本少时向同类共性分布收缩，明确 UNKNOWN/低置信度并允许等待；不为每个代码训练独立深度网络，不用代码记忆代替个性学习。
- 日线背景冻结在信号形成时；盘中只用决策点之前已完成 bar。画像中的收益/修复统计必须满足历史 label_end_ts < feature_asof，训练折拟合预处理及参数后冻结复用。股本、行业、公司行为、价格尺度与数据缺口沿用已有可见性/质量契约。
- 新特征未验收前仅生成研究数据或解释列，不静默并入线上评分；T1–T7 已失败的组合也不自动重新加入。

### 10.4 验证：分别证明选池和个性定价的增量

- 最小对照为“旧观察规则 / 新共性观察规则”与“共性 ATR 入场基线 / 加个性画像入场”两维消融。旧规则只作对照，保留可解释简单规则、逻辑回归/轻量树模型基线；不一开始全量深度重训。
- 同外层合格宇宙、数据源、时点、订单规模、费用与可执行退出约束；名单不同分别报告全池经济学、共同池配对结果、覆盖率及实际成交/空仓情况。不能用候选范围改变冒充排序提升，也不能只比较少数成功案例。
- 主评价是成本后可执行 3 日收益/增量，5 日为持有与尾部风险复核；盘中快速收回仅辅助标签，不等于赚钱。研究期限标签与动态退出策略账本分开，禁止未来最高点兑现、买入当日可卖或负 EV 强制填仓。
- 必须报告 STOP/左尾、校准、样本量、跨月/来源一致性、置信区间及真实现金股数账本；Rank IC 不能单独证明可交易。具体经济与统计门槛在看本轮结果前写入专属合同，不机械复制行业扩散实验门槛。
- 2024–2026 已参与多轮开发的区间不能重新称为纯净测试。时间划分按组隔离并 purge/embargo；晋级需预注册验证及代码冻结后未参与调参的前瞻影子证据，不能靠反复观察旧测试期选择参数。

## 是什么

## 查询协议（最重要的 5 条）
```python
import urllib.request, urllib.parse, msgpack
OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))  # 必须绕本机代理
def sdb(t, timeout=30):
    url = 'http://127.0.0.1:7899/?cmd=get&t=' + urllib.parse.quote(t)
    req = urllib.request.Request(url, headers={'Accept': 'application/x-msgpack'})
    raw = OPENER.open(req, timeout=timeout).read()
    d = msgpack.unpackb(raw, raw=False, strict_map_key=False)
    return d.get('data') if isinstance(d, dict) else d
# 键结构  表:代码:日期（裸 6 位代码，不带 sh/sz 前缀；日期可尾通配）
rows = sdb('日k:600000:20260928*')     # ← 精确日期必须带尾 *，否则返回空！
rows = sdb('日k:600000:*')             # 全历史
rows = sdb('分钟k:600000:20260928*')   # 当日分钟（240 根左右）
rows = sdb('板块*')                    # 1337 条板块（含 symbols 列表）
uni  = sdb('股票代码')                  # universe（dict of lists）
```
- **响应默认 msgpack**（requests 不带 Accept 也会拿到 msgpack → r.json() 会炸，这就是 D:/a股数据/build_increment.py 失败的原因；用 urllib+msgpack 最稳）
- **没有按日批量接口**：`日k:*:20260928` 返回空，只能逐票扫（全库分钟扫描 8 线程约 15-40 分钟，引擎高压下会崩，脚本要带重试+断点）
- 日k字段：date/code/name/open/high/low/close/pre_close/volume/amount/turnover/pct_chg/amplitude/is_st/vol_ratio/total_share/float_share/total_mv/float_mv/pe_ttm/pb
- 分钟k字段：code/date(14位int)/open/close/high/low/volume/amount（**原始未复权**；qfq 用日线 parts）
- 北交所（4/8/92 开头）**无分钟数据**；板块表 category='申万一级/二级/三级'/'概念'
