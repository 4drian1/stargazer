# R0-V1 板块 / 龙头上下文三层表设计（并發登记，标签核销后构建训练表）

状态：DESIGN_DRAFT（非训练就绪、非已实现）。本文件只登记**存储分层与字段契约**，不授权写母表、拟合或训练。
字段公式以 `R0_V1_DEVELOPMENT.md` §4.3/§4.4/§4.4.1/§4.4.2 为准，本文不重复定义，仅规定**三张表的边界、主键、可知时间与回填禁令**。

当前目标 = "五日不利价格风险"。板块与龙头是其**输入上下文**，**不必先各训练一个"板块强弱模型"和"龙头模型"**。
先用明确、可复现的统计字段；以后确需上游预测分数，再要求严格 OOT 输出，避免上游全样本预测泄漏到 R0。

## 0. 总体原则
- 并行登记定义：现在就把三张表的结构、规则版本、可知时间契约定下，但**不先训练它们**、**不先构建训练母表**。
- 训练母表的构建**须在标签核销之后**；标签未核销前，板块/龙头字段只做只读来源盘点与定义冻结。
- 业务有效日（effective date）**不自动证明当时已可知**；每张表须显式记录 `known_at`（PIT 可知时间），禁止用今日名单回填历史。

## 1. 板块身份表 `sector_identity`

记录"某股票在某时点属于哪个板块、该归属何时可知"，是 §4.4.1 板块身份/时间契约的物理落地。

| 列 | 含义 | 约束 |
|---|---|---|
| sector_key | 板块键（如 SW_L1 稳定代码 `801010`，非展示名） | 聚合键；名称仅展示 |
| sector_name_display | 板块展示名 | 不参与聚合 |
| classification_source | 分类体系（SW_L1 / GICS / 自定义） | 冻结 |
| rule_version | 分类规则 / 代码版本 hash | 变更即新行 |
| member_code | 成员股票代码 | |
| effective_from | 业务有效起始日 | 非"可知日" |
| effective_to | 业务有效截止日（当前有效=NULL） | |
| known_at | 该成员关系**当时可知**时刻 | 须 ≤ 使用该关系的决策时刻；缺失=NULL 且标 PENDING_SOURCE |
| source_snapshot_id / source_hash | 来源快照与 hash | 审计 |

- 主题/交易板块另有身份/版本，不与行业混用。
- 历史成员与生效时间来自 PIT 分类；主题成分历史可知证据未通过前，不把今日热点名单回填。
- 板块强但广度弱、个股弱而板块强均为待检验上下文，不赋予"安全/补涨"结论。

## 2. 龙头代表名单表 `leader_representative_list`

记录"机械选择的代表股集合、选择时刻与权重"，是 §4.4.2 龙头走势后置特征组的基础。

| 列 | 含义 | 约束 |
|---|---|---|
| list_id | 名单版本 id | |
| selection_rule_version | 选择规则版本 hash | K / 回看窗 / 资格 / 权重 / 更新频率 / 并列规则均冻结 |
| selection_method | 机械选择方法（如近 N 日成交额排序） | 不靠未来持续上涨确认历史龙头 |
| selection_as_of | 名单选择时刻 | |
| selection_known_at | 名单**可知**时刻 | 必须早于其被用作特征的决策时刻 |
| member_code | 代表股代码 | |
| weight | 成员权重（剔除目标股后归一） | 若目标自身是唯一代表且集合为空 → NULL，不可用目标自身走势证实其外部环境 |
| lookback_window / ranking_params / tie_break | 冻结参数 | 未签不生成字段 |

- **禁止事后赢家回填**：名单只由选择时刻之前已知数据机械得出；任何代表变更只作用于其可知之后。
- 固定名单与滚动名单的历史组合构造不得混用；缺历史名单/尺度/可用时刻保留缺失原因，不用现在龙头替换。

## 3. 候选上下文表 `candidate_context`

在**候选决策时刻**把板块强弱、广度、下行波动、回撤及代表股走势连接进来，是 §4.3/§4.4 字段的逐候选落地。

| 列 | 含义 | 来源表 |
|---|---|---|
| candidate_id | `hash(code, decision_time, candidate_rule_version, reference_rule, horizon, label_contract_version)` | 同标签主键 |
| decision_time / available_at | 决策时刻 / 上下文实际可用时刻 | |
| market_ret_5d/20d, market_vol_20d, market_downside_vol_20d, market_drawdown_20d, down_stock_ratio | 市场上下文（§4.3） | 独立冻结指数 |
| sector_key (FK) | 当时行业归属 | → `sector_identity` |
| sector_ret_5d/20d, sector_vs_market_5d/20d, sector_vol_20d, sector_downside_vol_20d, sector_drawdown_20d, sector_up_ratio, sector_down_ratio | 板块上下文（§4.4，剔除目标股后归一） | 由 `sector_identity` + 价格派生 |
| leader_list_id (FK) | 代表股名单版本 | → `leader_representative_list` |
| leader_ret_5d, leader_vs_sector_5d, leader_drawdown_20d, leader_downside_vol_20d, leader_breadth_divergence | 龙头代表组上下文（§4.4.2，剔除目标股后归一） | 由 `leader_representative_list` + 价格派生 |

- 全部字段截止决策时刻**实际可用**的已完成 P 日数据；次日板块/龙头盘中走势属另立盘中风险版本，不进入前一晚特征。
- 成员覆盖不足或基准为空记 NULL，不记 0；上涨/下跌比例因零收益成员存在，不默认互为 1 减对方。

## 4. 增量阶梯（沿用 `R0_V1_DEVELOPMENT.md` §5 模型阶梯）

每一步**固定**标签、人口、时间折与模型配置；用**同一保留比例**比较尾部风险增量，并**同报覆盖损失**，不按盈亏删缺失行或跨区域直接比分。

| 阶梯 | 输入组 | 比较基准 |
|---|---|---|
| S0 | 个股 + 市场 | 常数概率 B0 / 简单规则 B1 |
| S1 | + 板块上下文（表1+表3板块列） | 同 S0 配置，仅加板块组 |
| S2 | + 龙头代表组（表2+表3龙头列） | 同 S1 配置，仅加代表股组 |

- 不得同时换模型/改标签/扩人口并把收益归因于新增板块/龙头字段。
- 主检验顺序、多重比较处理、缺失规则、最差年份/板块恶化界限在 P3 冻结；板块/代表股增量须在**同保留数**下对照随机过滤、简单风险规则及未加该组的模型，按预注册时间块分报尾部触及率、MAE 左尾、Brier/LogLoss。
- 总体改善不能遮住某年份/板块严重恶化；代表股组未达门或数据不足则如实停止，不改龙头定义或回看窗救结果。

## 7. 字段注册与合成验收（无需先训练；下一项并行工作）

字段注册：表1/表2/表3 列定义以 §1–§3 为准；每个字段须登记**来源表 / 计算截止时刻 / 是否剔除目标股 / 空基准与缺失处理 / 版本 hash**。新增字段须经 §4 阶梯预注册，不得临时加入救结果。

合成验收（用合成数据验证三表构造逻辑的正确性，不依赖真实训练、不要求真实源）：
- **S-AC1 历史名单变更**：在 `t1` 生成的代表股名单，其后 `t2` 名单变更（成员增减/权重变化）**不得**回改 `t1` 时刻已落地的 `leader_*` 字段；即名单变更只作用于其 `selection_known_at` 之后，历史快照只读。断言：重算 `t1` 字段两次结果一致。
- **S-AC2 迟到数据**：某成员在 `t` 之后才到达的价格/名单，重算 `t` 时刻字段**不得**改变；迟到数据只影响 `t` 之后的窗口。断言：注入迟到样本前后 `t` 字段哈希不变。
- **S-AC3 候选自身是唯一代表股**：当目标股是某名单唯一成员、剔除后集合为空 → 相关 `leader_*` 字段必须 = NULL，**不得**用目标自身走势填充（否则用个股自身证实其"外部环境"）。断言：空集合 → NULL，非 0/非目标收益。
- **S-AC4 空基准**：板块成员不足或代表股集合为空 → 板块/代表股上下文字段 = NULL，不记 0；市场上下文独立、不受影响。断言：空基准行 NULL 且不污染 `candidate_id` 主键。
- **S-AC5 未来扰动不改变过去字段**：在 `t` 之后注入极端涨跌/公司行为/名单突变，**不得**改变 `t` 及之前任何已落地字段（无未来泄漏）。断言：注入前后 `t` 之前所有字段哈希一致。

- 上述验收**只验证构造与防泄漏逻辑**，不涉及预测能力；通过后才允许在标签核销后接真实源构建表3。
- 与 §4 阶梯一致：验收与后续增量实验**不**同时换模型、换标签、扩人口，否则无法判断增量来自哪里。
