# 自身板块覆盖与模型失真诊断（#18.109）

本轮只读诊断完成，6项合成算术/集合反例与独立静态集合、保存预测分解核验通过。未拟合模型、未改字段/准入/标签、未联网/部署。完整风险架构与原350字段模型均保留。

## 1. 为什么自身板块减速只有约3–4%覆盖

**主要是本版“完整成员”要求与已冻结源集合之间的结构性不匹配，不是“上涨减速无法量化”。**

| 检查 | 实测 |
| --- | ---: |
| 冻结板块集合 | 978 |
| 至少含一名冻结源外成员的板块 | 862 |
| 成员全部绑定本轮源的板块 | 116 |
| 未绑定本轮冻结源的成员代码 | 1344 |
| 所有所属板块均被静态阻断的研究股票 | 27 / 28 |
| 因上述条件不可能计算完整自身板块动能的研究行 | 82753 / 86319（95.87%） |

“源外”只指不在本实验已绑定的4196文件清单，不代表stockdb没有行情，也不证明停牌或未上市。本轮没有重新查询stockdb或盘点所有缓存。

仅600810的11个所属板块里有1个可能满足全成员要求：308192.TI（PA66）。它共3566行，是当前严格定义下的静态支持上限4.13%；再考虑必要bar和时钟关系，最终数值可比覆盖约3–4%。因此这些“自身板块减速”观察并不广泛代表28只股票或创新药等各主题。

代码路径：continuous_motion_matrix_v1.board_motion 用`n == total`判定完整成员；减速又依赖同日相邻区间。只要某个成员整段无绑定源，该板块所有时刻均不能满足前者。候选自身虽被剔除，仍不会补齐其他缺失成员。本轮已从冻结集合逐只复核这条阻断，不是假设。

全板块均值仍有值，是因为还有其他板块可观察，不代表每只候选所属板块也可观察。也不能用“新列在train不全为空”代替研究股票的覆盖广度。

没有再次逐槽解析4196分钟文件，因此不对剩余动态缺口给出伪精确的缺槽/停牌/日历原因分解；5分钟覆盖引用既有验收，静态成员阻断对5/15都成立。

## 2. Ridge失真来自哪里

用保存的350列预处理、700个系数和旧232字段，直接计算原字段数值及缺失指示的贡献；新增118块以保存原预测减去已知项形成代数残差。

| 段 | 截距 | 原232块平均贡献 | 新118块平均残差 | 原始平均预测 | 实际平均下探 |
| --- | ---: | ---: | ---: | ---: | ---: |
| train | 1.5523% | −0.3309pp | +0.0487pp | 1.2702% | 1.2702% |
| select | 1.5523% | −0.7068pp | +0.0243pp | 0.8698% | 1.2677% |
| calibration | 1.5523% | −0.0855pp | +6.1572pp | 7.6240% | 1.4105% |
| test | 1.5523% | −1.8284pp | +18.6600pp | 18.3839% | 1.4344% |

这证明当前保存模型在后段被新增块推高，但**不是独立重建118列，也不是唯一经济因果归因**。不能据此指定某一列“错误”后直接删去重训。

未发现保存标准化尺度小于1e-10，不能先宣告零方差标准化bug。确有输入分布外推：旧mb15_member_coverage的训练范围约0.6146–0.6601，test全部行在这个范围外；其平均标准化值约−42。另有部分覆盖字段偏离训练均值超过百个标准差。数据可用性变化可能被模型当成市场风险关系，必须与真正价格风险区分。

新118中具体哪列/数值/缺失指示主导，以及新增5分与15分各占多少，仍未唯一识别；需要重建相关侧表才可逐列确认。本轮没有为追求完整归因再扫描全部分钟或改模型。

## 3. LightGBM五月低估：不仅是股票构成变了

只针对该研究样本2026年5月：1031行、18个观察日、17只股票；多条120分钟标签重叠，不是1031次独立实验。

- 模型平均预测下探1.2570%，标签实际平均1.7013%，行加权低估0.4443个百分点。
- 日期等权偏差约−0.5520个百分点，低估并非只在行数权重上出现。
- train总体平均1.2702%；保持五月股票权重、使用每码train均值的诊断参考约1.2879%。相对train总体差异中，股票构成项仅+0.0177个百分点，其余约+0.4134个百分点为相对各码train均值的结果变化。
- 70行来自train未见代码，诊断参照显式用train总体均值；这是分解约定，不是补造输入/标签或新预测模型。上述分解不是因果证明，也未作显著性晋级判断。
- 例如300658的126行，平均预测1.3762%、实际3.6553%；其他代码有高估也有低估，完整逐码表保留，不只展示最坏例。

因此不能只换股票权重就认定问题解决，也不能据此认为黄金位置/板块/龙头整套框架无效。当前模型尚未稳定适应该样本后段更高的下探幅度。

## 4. 下一步建议：先改变可观察性的表达，不急着再拟合

优先评审“同一稳定共同成员的局部动能”诊断：在当前及前两根已完成bar中，只对三根都有有效行情的同一批成员计算局部减速，保持权重/身份不变，并同时报告全名单分母、共同成员数及覆盖率。

边界必须守住：

1. 它应叫共同成员篮子局部动能，不冒充完整板块指数或当时真实全板块。
2. 不能只剩一只共同成员就宣告板块可信；先披露支持分布，再另定准入，不按风险效果挑阈值。
3. 三根共同成员只能支撑局部变化，不能据此证明全天高点回吐。回吐须另有稳定全日路径证据，否则仍NULL。
4. 领涨股仍按当前涨幅识别、回落保留，同股先算再汇总；不因新口径换回成交量前三或删掉黄金/大盘/个股层。
5. 当前完整成员版本保留。若改变计算定义，须新版本及固定对照，不能在旧test上改到好看；本轮未启用新口径、未重训。

另一条路径是补齐未绑定源，但不能仅凭stockdb有数据就当所有历史窗口已验收，也不宜不估算资源就扩拉1344码。本轮不新增取数审批。

同时建议把覆盖漂移作为数据质量与置信度问题单列诊断，不让它悄悄替代价格风险；是否从可学习字段中分离覆盖指标，属于新白名单/模型对照决策，本轮不擅自执行。

## 6. 新局部动能（共同成员）定义与有界验证（第一轮评审，未验收）

按 §4 提出**新口径**：在每个 bar t 只使用在 t、t−1、t−2 **三根都有效**的同一批成员（按交易时段切分，不跨日/午休桥接），权重/身份不变（共同集内等权），输出**单列分母、共同成员数、覆盖率**，绝不冒充完整板块指数，也不替代全天高点回吐证据。

**代码组织与冻结身份（重要）**：新口径实现在**独立模块** `continuous_motion_common_v1.py`（不污染旧代码）；`continuous_motion_matrix_v1.py` 已**还原为精确冻结原版**（仅 `board_motion`/`context`/`schema`/`path_arrays`/`METRICS`，即产生当前模型/人口的代码），二者保持独立身份，旧模型权重对应的源码可审计、未被改动。"追加代码改变原模块哈希、不能再称原样保留"的问题已通过"独立新模块 + 还原冻结原版"解决。

- 第一轮离线反例 + 旧 test 共 22 项全过；但用户零网络复跑后，用额外反例发现 **5 处缺陷**（见 §7），已修复但**尚未验收、未替换旧口径**。
- **覆盖语义必须区分（避免误读）**：以下三者是不同统计对象，不能混为一谈：
  - 严格完整成员时点率 = 全板块成员**同时**齐全的时点比例（旧口径 gating 条件），~6.9%；
  - **真实有限值覆盖率** = 同一候选、同一时点存在可用共同篮子的比例（新口径实际可用观测率），5m≈**88.7%** / 15m≈**72.5%**；
  - **平均支持比（共同/名单）** = 在有限值处"共同成员数 ÷ 全名单"的均值，5m≈**62.0%** / 15m≈**61.7%**——这是**支持度披露**指标，**不代表有效特征覆盖率**。
  - 因此"7%→60%"不能直接成立；60% 仅作支持度披露，真实可用观测率约 89%/73%，但仍需同候选同口径下报告有限值覆盖率后再裁决。

| 频率 | 严格完整成员时点率 | 新口径真实有限值覆盖率(可用观测) | 有限值处平均支持比(共同/名单) | 有限值覆盖率≥0.5 的板块数/978 |
| --- | ---: | ---: | ---: | ---: |
| 5m | 6.91% | **88.7%** | 62.0% | **956** |
| 15m | 6.89% | **72.5%** | 61.7% | **954** |

结论：新口径可作"同一稳定共同成员"的可观察性表达；真实可用观测率显著（~89%/73%），但仅支撑局部变化，全天高点回吐仍需独立证据。模型/准入未改，未重训，未新增取数审批。

## 7. 第一轮评审发现的 5 处缺陷与修复（已修，未验收）

用户零网络复跑新测试 16 项 + 旧测试 6 项均通过后，用额外反例发现以下 5 处问题；均已修复于 `continuous_motion_common_v1.py`，并有对应回归反例（`test_continuous_motion_common_v1.py` 现 28 项）。新口径采用独立版本**并列验证，暂不替换旧口径**；`denominator`/`common_count`/`coverage` 先作为**审计与可信度字段**，不自动进入模型白名单。

1. **成员变化仍造假动能（已修）**：原实现每根先用各自共同集算篮子再比较相邻篮子，比较的成员可能不同。修复——**每个时刻固定同一共同集 `common(t)`**，`t`、`t−1`、`t−2` 三根水平全部用 `common(t)` 重算后再比较，相邻篮子不再跨成员集合。反例（两股价格不变、仅一只恢复数据）原会输出 +5% 收益与 5pp 减速，修复后为 0。
2. **午休仍被桥接（已修）**：原只清每日前两根，未清下午开盘前两根。修复——清零**每个交易时段（上午、下午）开盘前两根**（索引 `0,1` 与 `width/2, width/2+1`），下午 13:05/13:10 不再沿用上午成员记录。
3. **全板块统计被上涨板块统计覆盖（已修）**：原 `all`/`positive` 两范围写入同名字段，最终只剩上涨板块结果（`schema` 一致测试发现不了）。修复——两范围写入**不同字段名**（`cm_common{f}_all_*` 与 `cm_common{f}_positive_*`），`schema_common` 同步区分。
4. **领涨身份被替换（已修）**：排除候选自身后重新排名会把第二名提升为领涨。修复——**领涨身份先在全板（排除处理前）确定**，再仅在"该身份本身位于稳定共同集"时发布；真实领涨不可用时留缺失，不静默换人（反例：被排除的真领涨 → `current_deceleration` 全 NaN，不提升第二名）。
5. **篮子全天回吐字段全空且语义不当（已修/分离）**：原 `giveback` 因日初两根无共同窗口使前缀完整性全天无法恢复而全空；且三根局部动能不能证明全天回吐。修复——**篮子回吐（giveback）不发布为新口径字段**，明确分离、不作为已完成字段；仅发布局部减速与局部篮子收益，全天回吐另需稳定全日路径证据。

下一步：修复后按**同一候选、同一时点**报告真实有限值覆盖率，随后裁决是否做固定模型对照；是否替换/并列旧口径、是否将覆盖指标分离出可学习字段，属新白名单/模型对照决策，本轮不擅自执行。
