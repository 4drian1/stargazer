## 3. 决策时刻、区域来源与事件状态（修正 1、2）

### 3.1 两个时间必须分别记录，不可等同
- `signal_bar_ts`：信号 bar 的起始时间戳（例：`09:35`，信号 bar 开始）。
- `decision_available_ts`：字段**成为可知**的时刻 = **信号 bar 的完成时刻**（独立于成交）；未成交、延迟成交同样有此完成时刻（例：09:35 起始 bar 于 09:36 完成）。
- 二者**不相等**；字段值（如 `low`/`close` 取信号 bar 完成态）以 `decision_available_ts` 为可用门槛。**禁止使用「同一 bar 容差」掩盖二者时间偏差**，也不得写 `signal_bar_ts == decision_available_ts`，更不得用 `fill_ts` 充当可决策时刻。

### 3.2 区域来源逐分支明确（BASE_HOLD 不得套用 DIP 区域）
- `DIP_REPAIR` 事件：区域 = 本分支冻结的 MA20/BOLL_LOWER/PREVIOUS_DAY_LOW **合流区域**（来自 dip-scan 冻结产物），记录合并规则与全部 `anchor_sources`。
- `BASE_HOLD` 事件：区域 = **触发它的冻结箱体边界**（本分支原生边界），**不得从 DIP 扫描件给所有事件取区域**。
- 每事件须登记 `zone_source` 与 `zone_source_hash`；若无法证明该事件与所引区域的对应关系（来源缺失或分支错配）→ 标 `ZONE_SOURCE_MISMATCH` 缺失，**不强行套用**。

### 3.3 事件状态保留本分支原生类型
- `sig_type` 保留**各分支原生类型**，并**枚举实际保存的原生值**：构建步骤须从冻结件逐分支统计完整枚举集并登记，不得用「如……等」自由解释。
  - DIP_REPAIR：其原生状态枚举（以冻结件实际值为准，例如 APPROACH / BREAK / ALREADY_BELOW）。
  - BASE_HOLD：其箱体原生状态枚举（以冻结件实际值为准）。
- **禁止跨分支重映射**：不得把 BASE_HOLD 的 S1 等原生值强行编码为 BREAK/ALREADY_BELOW；跨分支类型不混用。

## 4. 字段清单与定义（修正 3；保留符号与审计分离）

候选触发时字段（截断至 `decision_available_ts`、冻结于事件开始，后续不随价格移动）：

- `pen_atr_bar = (zone_lower − low_at_decision_bar) / atr_ref` —— **保留符号，可为负，不截 0**。语义 =「信号 bar 穿透」，非截至 S 累计最大穿透。
- `d_atr = (close_at_decision_bar − zone_upper) / atr_ref` —— **保留符号**。
- `sig_type` —— 见 §3.3，本分支原生类型。
- `anchor_source` —— 区域锚点来源标识，逐事件登记：DIP_REPAIR 为 MA20 / BOLL_LOWER / PREVIOUS_DAY_LOW 之一或合流（记录合并规则与全部 `anchor_sources`）；BASE_HOLD 为其**实际冻结箱体来源与构造版本**（即使不属于三种锚点也须如实登记，**不得因非 MA/BOLL/前低而报 `ANCHOR_UNDEFINED`**）。
- `width_atr = (zone_upper − zone_lower) / atr_ref` —— 区域跨度。
- `signal_close` —— 决策 bar 收盘。

审计与模型输入分离：
- `signal_close`、区域绝对价格（`zone_upper`/`zone_lower` 绝对值）**可保存作审计列**（`audit_only=True`），但**不因此自动进入后续 LR 输入**；最终模型字段白名单另签。
- 明确排除：`future_reclaim_60m` 等后验收回标签属 CAR §4 后验表，**不得进入输入**。已完成 bar 收盘位置等「当时承接」信息无冻结定义，暂不纳入；**不得把 `pen_atr_bar`/`d_atr` 宣称为已验证「承接代理」**。
- 原四字段 `contraction`/`vol_cv10`/`setup`/`branch` 沿用冻结定义；**允许用冻结输入 + 原算法重建并核对来源哈希**，禁止重选触发点/区域或改冻结定义。

## 5. 防前视实测（全量 + 固定扰动样本）

原四字段的防前视证据**不自动继承**到新字段。须对每新增字段实测：

1. 截断性：字段仅依赖 `decision_available_ts` 及之前已完成 bar；注入该时刻之后的数据，字段值应不变。
2. 扰动不变性：扰动 `decision_available_ts` 之后的日线/分钟数据，事件时刻、区域、ATR、特征值均不变。
3. 多锚点区域：明确 `anchor` 单一/合流来源；合流须固定合并规则，**不任取一个锚点**。

验收分两层（全量 124 事件）：
- **第一层（既有量核对）**：事件时刻、分支、`zone_source`/`anchor_source`、区域绝对价格等**已有冻结记录**的字段，与冻结源逐事件比对，须一致。
- **第二层（新字段前缀一致性）**：对**无旧值**的新字段，比较「完整输入计算值」与「截至 `decision_available_ts` 的前缀计算值」，二者须相等（证明截断正确）。**真正没有旧值的字段须明确标注 `NO_BASELINE`，不得用本次生成值自证正确**。
- 边界案例覆盖：若所需边界案例在 124 事件中不存在，用**合成案例**覆盖（不另换研究人口）；合成案例单独登记，不混入 124 母人口统计。

固定扰动样本（**预注册、不随机**）：覆盖两分支（DIP_REPAIR / BASE_HOLD）、至少一个多锚点合流事件、以及时段边界（开盘近 09:35 / 收盘近 14:55 / 跨午休）案例；名单在构建前固定并登记哈希。

失败处理：**任一全量一致性或固定扰动样本失败，即停止发布字段表，不得静默删掉失败字段继续**；须输出失败清单与原因后停机。

## 6. 构建产物与缺失处理

- 物化**冻结字段表**（JSON）：每行 = 一个 `(code, E, segment, branch, setup)`，含 §4 字段 + `signal_bar_ts` + `decision_available_ts` + `zone_source`/`zone_source_hash` + 来源路径 + 计算版本 + 可用时刻 + 缺失原因码。
- 保留**完整行动人口状态表**：原 124 事件全量列出，逐字段 × 逐分支 × 逐段覆盖标记（`PRESENT` / `NULL`+原因）。
- **不填造缺失值，不按盈亏筛选事件**。
- 缺失仅当：本轮冻结输入本身缺失，或 §3.2 区域来源无法对应（`ZONE_SOURCE_MISMATCH`）。CAR 无覆盖**不**自动导致缺失。
- 缺失原因码：`TRIGGER_UNMAPPABLE`、`ZONE_SOURCE_MISMATCH`、`NO_FROZEN_INPUT`、`ZONE_SOURCE_UNRECORDED`、`NO_BASELINE`、`PREPROC_PENDING` 等。
