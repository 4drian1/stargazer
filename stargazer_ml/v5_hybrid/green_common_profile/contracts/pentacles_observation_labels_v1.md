# 星币侍从观察日记与走势标签合同 v1

记录部分 FROZEN_RECORDING_V1；精确标签部分为 DRAFT_REQUIRES_DATA_ACCEPTANCE。
日期：2026-10-07。授权仅涵盖日记实现与方案编制，不涵盖新分钟抓取、训练或买入决策。

## 1. 人口与版本

每次成功分析的全部候选入档，含无区域/不可用数据，不按后续涨跌筛选。
名单按规范 JSON（忽略重复分析的 created_at）内容 SHA256 保存为不可变版本。
同一天相同内容只登记一次；不同版本全部保留。同股不同版本不是独立样本。
记录观察日 monitor_date，不把盘后生成时间当作盘中观察时间。

## 2. 当前可记录字段

- 共性形态、名单原始字段、区域/依据、参考收盘、输入路径和哈希。
- 监控尝试状态：开启、关闭、等待、断流、错误、无效报价；未运行时没有心跳，不补造覆盖。
- first_observed_touch：首次有效轮询报价 ≤ zone_upper。区间内为 IN_ZONE，下方为 BELOW_ZONE。
- 首末有效报价、去重采样数、采样高低、到价后采样高低/末次相对变动、质量失败次数。
- 到价后采样末变动 = 末次有效采样价 / 首次观测触价 − 1。仅观察描述，不扣成本、不称交易收益。

不推断真正首次触价；不从日线 low 或当天累计 low 回填精确触发时刻。
重复/乱序报价不增加有效采样数，乱序显式记录。记录失败不影响原提醒，但 UI 显示停止原因。
全部记录附程序运行与源可见性限制；无有效观测不是“没触价”，更不是盈利/失败标签。

## 3. 精确走势标签（暂未启用）

固定目标为首次有效事件后的 30/60 交易分钟、观察日收盘、E 后第 3/5 个交易所交易日。
必须先签分钟源时间语义、时段网格、T0 是报价观测事件还是分钟确认事件、跨午休/跨日计数。
两个 T0 口径不得混用；若按报价 T0 研究，跨 T0 的未完成 bar 不得当作完整后续 bar。
窗口分别核对缺槽、重复、日期归属、价格有效性、数据版本、公司行为与价格口径。

主字段设计：窗口末变动、窗口内有利/不利极值、是否收回 zone_upper、首次收回耗时。
收回用已完成 close，不用 high；同 bar 顺序不可知则 AMBIGUOUS；从未跌破者不算修复成功。
缺失/未闭环/未知复权均 NULL，分窗独立；不能只看收盘 bar 在就认定完整。
H3/H5 行为观察不是可执行净收益：交易收益必须另用已签执行合同，T+1、止损、数量、成本、顺延各自核验。

当前 exact_labels 四窗均为 NULL/REQUIRES_VERIFIED_MINUTE_PATH。实现记录功能不代表这些标签已算出。
真实 OHLCV 尚不可得时，不允许从约 60 秒报价采样合成分钟 K、MAE/MFE 或净收益。

## 4. 存储与重放限制

输出位于桌面数据目录 data/pentacles_demo/journal：plans/*.json、days/YYYYMMDD.json/.md。
当前日文档随新观测更新，历史日期保留；完整名单不可变。JSON 可供后续数据整理，Markdown供阅读。
目录含临时文件设 2MiB 硬停止线，按实际字节和原子写入峰值预检；不承诺60天一定容纳。
这不是追加历史分钟或扩大原研究50MiB预算的许可；运行余量、长期保留和分钟快照额度另批。
保存的是报价摘要而非全部原始报价，不能独立重放每次轮询判断。精确标签需要另批可重放原始数据留存。

## 5. 验收与权限

必测：全候选、无区域、未观察到、同日多版本、真实哈希、重启去重、乱序、无效报价、预算、损坏、路径校验、日记失败不阻断提醒。
前瞻记录只从真实启动开始，不制造过去观测。用于训练/调优的日期不得再当作同版本独立前瞻验证。
本合同不更改共性阈值、区域构造、提醒触发条件或旧业务名单；不授权拟合、下单、上线新决策模型。
